## 二、数据库设计

### 2.1 改造表：`sessions`（会话表）

```sql
-- 最终目标表结构（含 auth 阶段新增的 user_id 列 + 本阶段新增的 deleted_at 列）
CREATE TABLE IF NOT EXISTS sessions (
    id          TEXT    PRIMARY KEY,              -- UUID (hex)
    title       TEXT    DEFAULT '',               -- 会话标题
    user_id     INTEGER,                          -- 关联 users.id（auth 阶段新增，本次依赖）
    status      TEXT    DEFAULT 'active',         -- 'active' | 'archived' | 'deleted'
    deleted_at  REAL,                             -- 【本次新增】软删除时间戳，NULL 表示未删除
    created_at  REAL    NOT NULL,                 -- 创建时间 (Unix timestamp)
    updated_at  REAL    NOT NULL,                 -- 最后更新时间 (Unix timestamp)
    FOREIGN KEY (user_id) REFERENCES users(id)
);

CREATE INDEX IF NOT EXISTS idx_sessions_user_id ON sessions(user_id);
CREATE INDEX IF NOT EXISTS idx_sessions_user_deleted ON sessions(user_id, deleted_at);
CREATE INDEX IF NOT EXISTS idx_sessions_updated ON sessions(updated_at DESC);
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `id` | TEXT | ✅ | UUID (hex)，主键，已有 |
| `title` | TEXT | — | 对话名称，已有 |
| `user_id` | INTEGER | — | auth 阶段新增，关联 users 表 |
| `status` | TEXT | ✅ | `active` / `archived` / `deleted`，已有（本次扩展） |
| `deleted_at` | REAL | — | **本次新增**，软删除时间戳，NULL=未删除 |
| `created_at` | REAL | ✅ | 已有 |
| `updated_at` | REAL | ✅ | 已有 |

**改造说明**：

| 变更类型 | 列名 | 说明 | 所属阶段 |
|---------|------|------|:--:|
| 新增 | `user_id` | 关联登录用户 | auth 阶段 |
| 新增 | `deleted_at` | 软删除标记，NULL 表示存活 | 本阶段 |
| 新增索引 | `idx_sessions_user_deleted` | 按用户查询未删除会话 | 本阶段 |
| 新增索引 | `idx_sessions_updated` | 按更新时间倒序排序 | 本阶段 |

**向后兼容策略**：
- `deleted_at` 默认为 NULL，所有旧数据视为未删除。
- 查询会话时统一加 `WHERE deleted_at IS NULL` 过滤。
- `DELETE` 操作不再物理删除行，改为 `UPDATE sessions SET deleted_at = ?`。

**DDL 迁移脚本**：

```sql
-- 迁移：为已有 sessions 表添加 deleted_at 列（幂等）
ALTER TABLE sessions ADD COLUMN deleted_at REAL;

CREATE INDEX IF NOT EXISTS idx_sessions_user_deleted ON sessions(user_id, deleted_at);
CREATE INDEX IF NOT EXISTS idx_sessions_updated ON sessions(updated_at DESC);
```

### 2.2 新建表：`feedback`（不满意反馈表）

```sql
CREATE TABLE IF NOT EXISTS feedback (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,   -- 反馈 ID，自增
    session_id  TEXT    NOT NULL,                     -- 关联 sessions.id
    user_id     INTEGER NOT NULL,                     -- 反馈用户 ID
    created_at  REAL    NOT NULL,                     -- 反馈时间 (Unix timestamp)
    status      TEXT    DEFAULT 'pending',            -- 'pending' | 'resolved'
    FOREIGN KEY (session_id) REFERENCES sessions(id),
    FOREIGN KEY (user_id) REFERENCES users(id)
);

CREATE INDEX IF NOT EXISTS idx_feedback_session ON feedback(session_id);
CREATE INDEX IF NOT EXISTS idx_feedback_user_session ON feedback(user_id, session_id);
CREATE UNIQUE INDEX IF NOT EXISTS idx_feedback_unique ON feedback(user_id, session_id);
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `id` | INTEGER | ✅ | 自增主键 |
| `session_id` | TEXT | ✅ | 关联会话 ID |
| `user_id` | INTEGER | ✅ | 反馈用户 ID |
| `created_at` | REAL | ✅ | 反馈时间，Unix 时间戳 |
| `status` | TEXT | ✅ | `pending`（待处理）/ `resolved`（已处理），默认 `pending` |

> **唯一约束**：`(user_id, session_id)` 联合唯一索引，确保同一用户对同一会话只能反馈一次。重复点击由前端提示拦截，后端作为兜底。

#### 3.1.1 POST `/api/chat` — 发送消息 / 新建会话

- **功能**：发送用户消息到指定会话并获取 AI 流式回复；支持新建会话模式
- **认证**：需要 Bearer Token（通过 `get_current_user` 注入）

**请求体 (Request Body)**：
```json
// 发送消息
{
  "session_id": "a1b2c3d4e5f6...",
  "message": "我想咨询退款流程",
  "new_session": false
}

// 新建会话
{
  "session_id": "",
  "message": "",
  "new_session": true
}
```

**校验规则**：

| 字段 | 规则 | 错误提示 |
|------|------|---------|
| `message` | `new_session=false` 时必须非空 | "message is required" |
| `session_id` | `new_session=false` 时对应的 session 必须存在且未被软删除 | "session not found" |

**SSE 事件类型**：

| event 类型 | data 结构 | 说明 |
|-----------|----------|------|
| `reasoning` | `{"content": "<think>"}` / `{"content": "思考内容..."}` / `{"content": "</think>"}` | 思考过程开始/内容/结束标记 |
| `content` | `{"content": "最终回复片段"}` | 最终回复流式内容 |
| `task` | `{"type": "knowledge_retrieval", "status": "executed", "result": "..."}` | Skill 任务执行结果 |
| `warning` | `{"content": "警告信息"}` | 非致命警告（如 token 超限） |
| `error` | `{"content": "错误信息"}` | 致命错误 |
| `done` | `{}` | 流结束 |

**SSE 完整流示例**：
```
event: reasoning
data: {"content": "<think>"}

event: reasoning
data: {"content": "用户询问退款流程，需要检索退款政策..."}

event: reasoning
data: {"content": "</think>"}

event: content
data: {"content": "退款流程如下：\n1. 进入"}

event: content
data: {"content": "「我的订单」页面..."}

event: task
data: {"type": "knowledge_retrieval", "status": "executed", "result": "找到3条退款规则..."}

event: done
data: {}
```

**成功响应**：`200 OK`，`Content-Type: text/event-stream`，响应头含 `X-Session-Id`。

**失败响应**：
```json
// 消息为空 (400 Bad Request)
{"detail": "message is required"}

// API Key 未配置 (500 Internal Server Error)
{"detail": "ARK_API_KEY not configured"}
```

> **改造点**：
> 1. 所有接口注入 `current_user`（已有 `Depends(get_current_user)`，本次确保生效）。
> 2. `new_session=true` 时必须传入 `user_id` 创建有主会话。
> 3. SSE 断连后 `EventSource.onerror` / `reader` 异常由前端处理（显示重新生成按钮），后端无需额外逻辑。

#### 3.1.2 GET `/api/sessions` — 获取对话列表

- **功能**：按更新时间倒序获取当前用户的会话列表，支持分页
- **认证**：需要 Bearer Token

**查询参数**：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:--:|--------|------|
| `limit` | int | — | 10 | 每页条数，最大 50 |
| `offset` | int | — | 0 | 偏移量，用于瀑布流分页 |

**成功响应 (200 OK)**：
```json
{
  "sessions": [
    {
      "id": "a1b2c3d4...",
      "title": "退款咨询",
      "status": "active",
      "user_id": 1,
      "last_message": "那超过7天还能退吗？",
      "created_at": 1717286400.0,
      "updated_at": 1717290000.0
    },
    {
      "id": "e5f6g7h8...",
      "title": "新对话",
      "status": "active",
      "user_id": 1,
      "last_message": "您好，我是低代码平台智能客服...",
      "created_at": 1717280000.0,
      "updated_at": 1717280000.0
    }
  ],
  "total": 25,
  "has_more": true
}
```

**失败响应 (401 Unauthorized)**：
```json
{"detail": "无效的认证令牌"}
```

> **改造点**：
> 1. 查询条件增加 `WHERE user_id = ? AND deleted_at IS NULL`。
> 2. 增加 `last_message` 字段：子查询 `messages` 表中该 session 的最新一条 visible 消息内容。
> 3. 增加 `offset` / `limit` 分页，返回 `total` 和 `has_more`。
> 4. `last_message` 在超出 50 字符时由前端截断显示（后端不做截断）。

#### 3.1.3 GET `/api/sessions/{session_id}/messages` — 获取会话消息

- **功能**：获取指定会话的所有可见消息
- **认证**：需要 Bearer Token

**查询参数**：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:--:|--------|------|
| `limit` | int | — | 50 | 每次加载条数 |
| `before_id` | int | — | — | 游标：加载该消息 ID 之前的更早消息（向上滚动加载更多） |

**成功响应 (200 OK)**：
```json
{
  "session_id": "a1b2c3d4...",
  "messages": [
    {
      "id": 1,
      "role": "assistant",
      "content": "我是低代码平台智能客服，请问我有什么可以帮您？",
      "reasoning_content": "",
      "created_at": 1717286400.0
    },
    {
      "id": 2,
      "role": "user",
      "content": "我想咨询退款流程",
      "reasoning_content": "",
      "created_at": 1717286460.0
    },
    {
      "id": 3,
      "role": "assistant",
      "content": "退款流程如下：...",
      "reasoning_content": "用户询问退款流程，需要检索退款政策...",
      "created_at": 1717286520.0
    }
  ],
  "has_more": false
}
```

**失败响应 (404 Not Found)**：
```json
{"detail": "会话不存在"}
```

> **改造点**：
> 1. 返回 `messages` 中每条消息增加 `id` 和 `created_at` 字段（用于向上滚动游标分页和时间戳显示）。
> 2. 过滤 `<task_result>` 前缀的用户消息（已有逻辑 `isVisibleMessage`）。
> 3. 软删除的会话仍可读取消息（供管理员后台审查）。

#### 3.1.4 DELETE `/api/sessions/{session_id}` — 软删除对话

- **功能**：将指定会话标记为已删除（设置 `deleted_at`）
- **认证**：需要 Bearer Token

**成功响应 (200 OK)**：
```json
{"ok": true}
```

**失败响应**：
```json
// 会话不存在或不属于当前用户 (404 Not Found)
{"detail": "会话不存在"}

// 会话已被删除 (409 Conflict)
{"detail": "会话已删除"}
```

> **改造点**：从硬删除（`DELETE FROM messages/sessions`）改为软删除（`UPDATE sessions SET deleted_at = ?`）。消息保留不删，供管理员查看。

### 3.3 上下文截断逻辑

**文件**：`backend/routers/chat.py`（在 `_agent_loop_stream` 或消息准备阶段）

**规则**：
- 大模型上下文窗口有限（豆包模型约 128K tokens），当对话历史过长时需截断。
- 从 **头部**（最早的消息）开始丢弃，保留最近的消息对。
- 截断阈值：估计 token 数 ≈ 字符数 / 3，当总字符数超过 **64000**（约 21000 tokens，为 128K 留足空间）时触发截断。
- 保留完整的 system messages + 截断后的对话历史。
- 截断粒度：至少保留最近 **10 轮对话**（20 条消息），即使用户对话极长。

**实现伪代码**：
```python
MAX_CONTEXT_CHARS = 64000
MIN_RETAIN_ROUNDS = 10  # 最少保留 10 轮对话

def truncate_messages(system_msgs: list, history_msgs: list) -> list:
    total = sum(len(m["content"]) for m in system_msgs + history_msgs)
    if total <= MAX_CONTEXT_CHARS:
        return system_msgs + history_msgs

    # 从头部丢弃，但至少保留 MIN_RETAIN_ROUNDS * 2 条
    min_retain = MIN_RETAIN_ROUNDS * 2
    truncated = history_msgs
    while len(truncated) > min_retain:
        total = sum(len(m["content"]) for m in system_msgs + truncated)
        if total <= MAX_CONTEXT_CHARS:
            break
        truncated = truncated[2:]  # 每次丢弃一轮（user + assistant）

    return system_msgs + truncated
```

#### 4.1.2 交互逻辑

##### 4.1.2.1 页面初始化

```
ChatView.vue mounted (onMounted)
    → 从 useAuth() 获取 currentUser
    → 调用 loadSessions() 加载对话列表（首次 10 条）
        ├─ 列表为空 → 自动调用 handleNewChat() 创建新对话
        └─ 列表不为空 → 选中第一条对话，加载其历史消息
    → 监听 window resize（移动端不处理）
```

##### 4.1.2.2 新对话

```
handleNewChat()
    → 若 isStreaming → 忽略
    → 调用 POST /api/chat { new_session: true }
        ├─ 返回 SSE 流（仅 done 事件）
        └─ 从响应头 X-Session-Id 获取新 session ID
    → 重新调用 loadSessions()
    → 设置 currentSessionId = 新 ID
    → 加载该会话消息（含 AI 问候语）
    → 滚动到底部
```

##### 4.1.2.3 发送消息

```
sendMessage()
    → 若 !inputText.trim() || isStreaming → 忽略
    → 若 !currentSessionId → 先执行 handleNewChat()
    → 保存用户消息到本地 messages[]（右对齐气泡）
    → inputText = ''（清空输入框）
    → isStreaming = true，输入框置灰，按钮切换为"停止"
    → 创建空 AI message 对象（含 isStreaming、reasoning、content）
    → 调用 streamChat() 发起 SSE 连接
        ├─ onContent: 逐段追加到 AI message.content
        ├─ onReasoning: 逐段追加到 AI message.reasoning
        ├─ onTask: 记录 skill 调用
        ├─ onError: 显示网络错误提示 / "重新生成"按钮
        ├─ onDone: isStreaming = false，恢复输入框和按钮
        └─ abort: 用户点击停止
    → 每次收到 delta 时判断是否在底部 → 自动滚动（仅在底部时跟随）
```

##### 4.1.2.4 停止生成

```
stopStreaming()
    → abortController.abort()
    → isStreaming = false
    → 最后一个 AI message.isStreaming = false
    → 已输出内容保留在气泡中（不入库已在后端保证）
    → 按钮恢复为"发送"，输入框恢复可用，内容不清空
```

##### 4.1.2.5 SSE 断连处理

```
SSE 连接意外断开（fetch catch / reader 异常）
    → AI message.isStreaming = false
    → AI message.showRegenerate = true（显示"🔄 重新生成"按钮）
    → isStreaming = false，恢复按钮和输入框

handleRegenerate(msg)
    → 保存原 message 引用
    → msg.content = ''，msg.reasoning = ''，msg.showRegenerate = false
    → 重新调用 sendMessage() 的逻辑（但不再新增用户消息）
    → 流式内容覆盖原气泡
```

### 5.7 路由守卫判断流程

```
router.beforeEach((to, from, next)
    → 检查 localStorage.getItem('auth_token')
        ├─ 有 token & to.path === '/login' 或 '/register'
        │   → next('/chat')
        │
        ├─ 有 token & to.path === '/chat'
        │   → 验证 Token 有效性（GET /api/me）
        │       ├─ 200 → next()
        │       └─ 401 → 清除 token → next('/login')
        │
        ├─ 无 token & to.path === '/chat'
        │   → next('/login')
        │
        └─ 无 token & to.path === '/login' 或 '/register'
            → next()
```

### 5.8 API 请求拦截逻辑

```
authFetch(url, options)
    → token = localStorage.getItem('auth_token')
    → headers['Authorization'] = `Bearer ${token}`
    → fetch(url, { ...options, headers })
        ├─ resp.status === 401
        │   → localStorage.removeItem('auth_token')
        │   → localStorage.removeItem('user_info')
        │   → window.location.href = '/login'
        │   → throw
        ├─ resp.ok → return resp
        └─ 其他错误 → throw
```

### 8.3 数据库迁移说明

本次迭代需要为 `sessions` 表新增 `deleted_at` 列，并创建 `feedback` 表：

```bash
# 方式一：手动执行 SQL（开发环境）
sqlite3 backend/data/app.db < migration.sql
```

```sql
-- migration.sql
ALTER TABLE sessions ADD COLUMN deleted_at REAL;

CREATE INDEX IF NOT EXISTS idx_sessions_user_deleted ON sessions(user_id, deleted_at);
CREATE INDEX IF NOT EXISTS idx_sessions_updated ON sessions(updated_at DESC);

CREATE TABLE IF NOT EXISTS feedback (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id  TEXT    NOT NULL,
    user_id     INTEGER NOT NULL,
    created_at  REAL    NOT NULL,
    status      TEXT    DEFAULT 'pending',
    FOREIGN KEY (session_id) REFERENCES sessions(id),
    FOREIGN KEY (user_id) REFERENCES users(id)
);

CREATE INDEX IF NOT EXISTS idx_feedback_session ON feedback(session_id);
CREATE INDEX IF NOT EXISTS idx_feedback_user_session ON feedback(user_id, session_id);
CREATE UNIQUE INDEX IF NOT EXISTS idx_feedback_unique ON feedback(user_id, session_id);
```

> **建议**：在 `session_service.py` 的 `_init_db()` 中直接执行 `ALTER TABLE ... ADD COLUMN`（使用 `IF NOT EXISTS` 模式的 try/except），实现自动迁移。

## 十、补充考量

### 10.1 错误处理与边界情况

| 场景 | 前端处理 | 后端处理 |
|------|---------|---------|
| Token 过期 / 无效 | `authFetch` 拦截 401，清除 token，跳转 `/login` | 返回 `401 Unauthorized` |
| 网络中断 | fetch catch 显示 "当前网络似乎不太稳定，请稍后重试～" 气泡 | — |
| SSE 流中断 | 已输出内容保留 + 显示「🔄 重新生成」按钮 | 无额外处理 |
| 消息为空 | 发送按钮 disabled + Enter 不触发 | `400 "message is required"` |
| 会话不存在 | `404` 时提示 "会话不存在"，刷新列表 | `404 "会话不存在"` |
| 资源不属于当前用户 | `authFetch` 统一处理 403 | 查询时 `WHERE user_id = ?` |
| 空对话列表 | 自动调用 `handleNewChat()` 创建新对话 | 返回空数组 `{ sessions: [], total: 0 }` |
| 并发冲突（重复反馈） | 前端检查 `hasFeedback` + 后端唯一约束兜底 | `409 Conflict` + 唯一索引 |
| XSS 防护 | `marked` 渲染前不做额外转义；链接 `target="_blank" rel="noopener"` | 参数化 SQL + Pydantic 校验 |
| IME 输入法 | `compositionstart`/`compositionend` 标志位，composing 期间 Enter 不发送 | — |
| 停止生成后 partial 内容 | 前端保留显示，不持久化 | `append_message` 仅在完整结束后调用 |
| 侧边栏拖拽边界 | clamp 200~500px，主区域 min-width 400px 保护 | — |
| API Key 未配置 | 显示通用错误 | `500 "ARK_API_KEY not configured"` |
| 数据库文件不存在 | — | `_init_db()` 自动创建目录 + 文件 |
| 上下文超限 | 无感知 | 后端截断旧消息（字符数估算） |

### 10.2 安全性关注点

| 关注点 | 措施 |
|--------|------|
| Token 存储 | `localStorage`，`authFetch` 自动注入 Authorization Header |
| Token 有效期 | 7 天过期（JWT `exp` 声明），由 `dependencies/auth.py` 校验 |
| XSS | 不使用 `v-html` 渲染用户输入内容；AI 回复使用 `marked` + `DOMPurify.sanitize()` |
| CSRF | SPA + Bearer Token 认证，不依赖 Cookie |
| SQL 注入 | 后端全部使用参数化 SQL（`?` 占位符） |
| 敏感信息保护 | `JWT_SECRET`、`ARK_API_KEY` 存储在 `.env`，不提交版本控制 |
| CORS | FastAPI 后端仅允许前端开发域 |

### 10.3 性能考量

| 场景 | 措施 |
|------|------|
| 对话列表分页 | offset/limit 分页，每次 10 条 |
| 消息历史分页 | 游标分页（`before_id`），每次 50 条 |
| 侧边栏渲染 | 虚拟滚动（如列表 >100 条时考虑，本次先不做） |
| 流式渲染 | SSE 逐 token 追加 DOM，不做全量 re-render |
| Markdown 渲染 | `marked.parse()` 仅在消息完成时调用；流式输出时用纯文本 + `▊` 光标 |
| 数据库连接 | SQLite 单文件，WAL 模式，已启用 |
| `last_message` 查询 | 子查询仅取最新 1 条，性能 OK |

### 10.4 兼容性规划

| 项目 | 说明 |
|------|------|
| 数据库兼容 | `deleted_at` 新增列，旧数据默认 NULL；`ALTER TABLE ADD COLUMN` 幂等 |
| API 向后兼容 | `list_sessions` 响应新增 `last_message`、`total`、`has_more` 字段，旧客户端忽略新字段 |
| 前端兼容 | `ChatView.vue` 重写，不保留旧版兼容 |
| 初始数据方案 | 新用户首次进入自动创建一条对话（含 AI 问候语） |
| 移动端适配 | 暂不做 |

### 10.6 开发规范

- **命名规范**：Vue 组件 `PascalCase`（`ChatView.vue`），后端文件 `snake_case`（`feedback.py`、`feedback_service.py`），API 路径 `kebab-case`（`/api/sessions`）
- **注释规范**：关键业务逻辑（上下文截断、软删除、滚动行为）必有注释
- **Git 提交规范**：`feat:` / `fix:` / `docs:` / `refactor:`
- **类型安全**：TypeScript 严格模式，后端 Pydantic 覆盖所有请求/响应模型
- **CSS 规范**：使用 `scoped` 样式，颜色值引用 CSS 变量，不硬编码色值
- **文件路径**：前端 `frontend/src/` 为根，后端 `backend/` 为根
