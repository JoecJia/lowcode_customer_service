**数据流向说明**：

- 每条 SSE 流只在前端回调中更新 `runtimes[sid].messages`，**不写入其他会话的缓存**；
- 视图只渲染 `runtimes[currentSessionId].messages`，后台会话的流不触发当前视图 DOM 更新；
- 生成标志来自前端内存，不经过后端，因此跨标签页不同步（需求 N1）。

|------|------|:--:|---------|---------|
| `POST` | `/api/chat`（`new_session=true`） | ✅ | 已有，无改动 | 新建对话；响应头 `X-Session-Id`；SSE 仅一个 `done` |
| `POST` | `/api/chat`（`session_id=xxx`） | ✅ | 已有，无改动 | 发送消息 / 重新生成；返回 SSE 流 |

#### 4.1.2 交互逻辑（文本流程图）

```
用户点击「新建对话」
    → ensureRuntime(newSid)
    → 当前视图切换到 newSid
    → 旧会话 runtime.generating 保持 true（流不中断）
    → 失败 → ElMessage.warning("新建对话失败，请重试")，视图不变

用户点击对话列表项 sid
    ├─ sid === currentSessionId → no-op（不加载、不动流）
    ├─ runtimes[sid] 不存在     → loadMessages(sid) + initialized=true
    ├─ runtimes[sid].generating → 直接用缓存，跳过 loadMessages
    └─ 其他 → 用缓存（可选刷新）
    → 保存旧会话草稿/滚动位置，恢复新会话草稿/滚动位置

用户在当前会话发送消息
    → 校验 !runtime.generating
    ├─ 为 false → ElMessage.warning("当前对话正在生成中")，拦截
    └─ 为 true  → 本地追加 user / assistant 消息到 runtime.messages
                  → markGenerating(sid, controller, assistantMsg)
                  → streamChat(sid, ...) 回调写入 runtime.messages
                  → done / error / abort → finishGenerating(sid)

用户点击「停止」
    → stopStreaming(currentSessionId)
    → runtime.controller.abort() → finishGenerating(sid, {stopped:true})
    → 仅当前会话标志消失，后台其他会话不受影响

用户删除对话
    → ElMessageBox.confirm
    → disposeRuntime(sid)（先 abort，再清理缓存）
    → apiDeleteSession(sid) → loadSessions()
    → 若删的是当前会话 → 切换到第一条 / 自动新建
```

#### 4.1.3 前端校验规则

| 字段 / 操作 | 规则 | 错误消息 | 触发时机 |
|------------|------|---------|---------|
| 同一会话发送消息 | `runtimes[sid].generating === false` | "当前对话正在生成中" | `sendMessage()` 入口、竞态二次校验 |
| 同一会话重新生成 | `runtimes[sid].generating === false` | "当前对话正在生成中" | `handleRegenerate()` 入口 |
| 流回调写入 | `isActiveCallback(sid, controller)` 为 true | 静默丢弃 | 每个 `onContent/onReasoning/onTask/onDone/onError` 首行 |
| 新建对话 | 无生成状态限制 | 网络失败时 "新建对话失败，请重试" | `handleNewChat()` |
| 删除对话 | 无生成状态限制；先中断流 | — | `handleDeleteSession()` |
| 空消息 + 无附件 | 沿用现有规则，不发送 | — | `sendMessage()` |

### 4.2 输入组件 `ChatInput.vue`（小改造）

**文件**：`frontend/src/components/ChatInput.vue`

| 改造项 | 当前状态 | 目标状态 |
|--------|---------|---------|
| `streaming` prop | 跟随全局 `isStreaming` | 跟随 `isCurrentStreaming`（**仅当前会话**） |
| 文本 `text` ref | 组件内部独立 | 受控：`modelValue` + `update:modelValue`，草稿由父组件按会话保存 |
| 附件草稿 | 组件内部独立 | 本迭代先清空（不跨会话串用）；P1 可通过 `takeDraft/restoreDraft` 增强 |

```typescript
// frontend/src/components/ChatInput.vue（关键改造片段）
const props = defineProps<{
  streaming: boolean
  modelValue?: string
}>()

const emit = defineEmits<{
  send: [payload: { text: string; attachments: AttachmentPayload[] }]
  stop: []
  'update:modelValue': [value: string]
}>()

const text = computed({
  get: () => props.modelValue ?? '',
  set: (v: string) => emit('update:modelValue', v),
})

async function handleSend() {
  if (!canSend.value) return
  const payloads = await getPayloads()
  emit('send', { text: text.value.trim(), attachments: payloads })
  emit('update:modelValue', '')   // 替换原 text.value = ''
  reset()
}
```

> ⚠️ 父组件必须绑定 `v-model="currentDraft"`，其中 `currentDraft` 为计算属性，读写 `runtimes[currentSessionId].draft`。

## 七、状态管理与全局配置

### 7.1 新增 composable：`frontend/src/composables/useSessionRuntimes.ts`

> 设计要点：泛型化消息类型，避免把 `UIMessage` 从 `ChatView.vue` 抽成独立文件；用 `reactive` 对象而非 `Map`，保证模板与计算属性可直接追踪。

```typescript
import { computed, reactive } from 'vue'

export interface SessionRuntime<TMessage> {
  sessionId: string
  /** 是否正在生成；唯一权威来源 */
  generating: boolean
  /** 当前流的控制器；generating=false 时应为 null */
  controller: AbortController | null
  /** 当前流正在写入的消息对象引用，停止时精确定位，不靠数组末尾猜测 */
  streamingMessage: TMessage | null
  /** 该会话消息缓存（含流式半成品） */
  messages: TMessage[]
  /** 是否已加载过历史消息 */
  initialized: boolean
  /** 该会话独立的输入草稿 */
  draft: string
  /** 该会话消息区滚动位置 */
  scrollTop: number
  /** 最近一次生成错误；非空时展示失败态 */
  error: string | null
}

export function useSessionRuntimes<TMessage>() {
  const runtimes = reactive<Record<string, SessionRuntime<TMessage>>>({})

  function getRuntime(sid: string): SessionRuntime<TMessage> | undefined {
    return runtimes[sid]
  }

  /** 获取或创建运行时（幂等） */
  function ensureRuntime(sid: string): SessionRuntime<TMessage> {
    if (!runtimes[sid]) {
      runtimes[sid] = {
        sessionId: sid,
        generating: false,
        controller: null,
        streamingMessage: null,
        messages: [],
        initialized: false,
        draft: '',
        scrollTop: 0,
        error: null,
      }
    }
    return runtimes[sid]
  }

  /**
   * 回调守卫：只有「运行时存在 + 仍标记生成中 + 控制器未更换 + 未 abort」
   * 四者同时满足，回调才允许写入。防止已删除会话 / 已停止流 / 迟到的 error 污染数据。
   */
  function isActiveCallback(sid: string, controller: AbortController): boolean {
    const rt = runtimes[sid]
    return !!rt
      && rt.generating
      && rt.controller === controller
      && !controller.signal.aborted
  }

  /** 开始生成；若该会话已在生成则返回 false（同会话防并发） */
  function markGenerating(
    sid: string,
    controller: AbortController,
    streamingMessage: TMessage,
  ): boolean {
    const rt = ensureRuntime(sid)
    if (rt.generating) return false
    rt.generating = true
    rt.controller = controller
    rt.streamingMessage = streamingMessage
    rt.error = null
    return true
  }

  /** 结束生成；幂等。success=false 且 error 非空时进入失败态 */
  function finishGenerating(
    sid: string,
    result: { success?: boolean; error?: string | null; stopped?: boolean } = {},
  ): void {
    const rt = runtimes[sid]
    if (!rt || !rt.generating) return
    rt.generating = false
    rt.controller = null
    if (result.error) rt.error = result.error
    else if (!result.stopped) rt.error = null
    rt.streamingMessage = null
  }

  /** 中断并清理运行时（删除会话 / 页面卸载时调用） */
  function disposeRuntime(sid: string): void {
    const rt = runtimes[sid]
    if (!rt) return
    rt.controller?.abort()
    delete runtimes[sid]
  }

  function disposeAllRuntimes(): void {
    Object.keys(runtimes).forEach(disposeRuntime)
  }

  const generatingSessionIds = computed(() =>
    Object.keys(runtimes).filter(sid => runtimes[sid].generating),
  )

  function isSessionGenerating(sid: string): boolean {
    return !!runtimes[sid]?.generating
  }

  return {
    runtimes,
    getRuntime,
    ensureRuntime,
    isActiveCallback,
    markGenerating,
    finishGenerating,
    disposeRuntime,
    disposeAllRuntimes,
    generatingSessionIds,
    isSessionGenerating,
  }
}
```

### 7.2 `ChatView.vue` 关键改造代码

```typescript
// ① 引入 composable，删除旧的全局 isStreaming / abortController / messages
const {
  runtimes,
  ensureRuntime,
  isActiveCallback,
  markGenerating,
  finishGenerating,
  disposeRuntime,
  disposeAllRuntimes,
  isSessionGenerating,
} = useSessionRuntimes<UIMessage>()

// ② 派生状态
const currentRuntime = computed(() =>
  currentSessionId.value ? ensureRuntime(currentSessionId.value) : undefined,
)
const isCurrentStreaming = computed(() => !!currentRuntime.value?.generating)
const currentMessages = computed<UIMessage[]>(() => currentRuntime.value?.messages || [])
const currentDraft = computed({
  get: () => currentRuntime.value?.draft || '',
  set: (v: string) => { if (currentRuntime.value) currentRuntime.value.draft = v },
})

// ③ 切换会话：移除全局拦截 + 缓存优先
async function handleSelectSession(sid: string) {
  if (sid === currentSessionId.value) return          // 点当前会话：空操作
  if (currentSessionId.value) saveViewState(currentSessionId.value)

  currentSessionId.value = sid
  const rt = ensureRuntime(sid)

  if (!rt.initialized) {
    await loadMessages(sid)                           // loadMessages 写入 rt.messages
    rt.initialized = true
  }
  // rt.generating === true 时直接用缓存，跳过 loadMessages
  await loadFeedbackStatus(sid)
  restoreViewState(sid)
  await nextTick()
  scrollToBottom()
}

function saveViewState(sid: string) {
  const rt = runtimes[sid]
  if (!rt) return
  rt.scrollTop = messageArea.value?.scrollTop || 0
}
function restoreViewState(sid: string) {
  const rt = runtimes[sid]
  if (!rt) return
  nextTick(() => {
    if (messageArea.value) messageArea.value.scrollTop = rt.scrollTop
  })
}

// ④ 新建对话：移除全局拦截
async function handleNewChat() {
  try {
    const sid = await createSession()
    if (!sid) return
    ensureRuntime(sid)
    await loadSessions()
    if (currentSessionId.value) saveViewState(currentSessionId.value)
    currentSessionId.value = sid
    await loadMessages(sid)
    runtimes[sid].initialized = true
    hasFeedback.value = false
    await nextTick()
    scrollToBottom()
  } catch {
    ElMessage.warning('新建对话失败，请重试')
  }
}

// ⑤ 发送消息：按会话写入 + 回调守卫
async function sendMessage(text: string, attachmentPayloads: AttachmentPayload[] = []) {
  if ((!text.trim() && !attachmentPayloads.length)) return

  if (!currentSessionId.value) {
    await handleNewChat()
    if (!currentSessionId.value) return
    await new Promise(r => setTimeout(r, 150))
  }
  const sid = currentSessionId.value
  const rt = ensureRuntime(sid)
  if (rt.generating) {
    ElMessage.warning('当前对话正在生成中')
    return
  }

  rt.messages.push(userMsg /* 见现有构造逻辑 */)
  await nextTick()
  scrollToBottom()

  const assistantMsg = reactive<UIMessage>({
    role: 'assistant', content: '', reasoning: '', steps: [],
    showThinking: true, isStreaming: true,
  })
  rt.messages.push(assistantMsg)
  _thinkingContentEl = null

  const controller = streamChat(
    sid, text,
    (chunk) => {
      if (!isActiveCallback(sid, controller)) return
      if (!assistantMsg.content && chunk) assistantMsg.showThinking = false
      assistantMsg.content += chunk
      breakReasoningStep(assistantMsg)
      scheduleRender(assistantMsg)
      scheduleStreamScroll(sid)                      // 非当前会话不滚动
    },
    (chunk) => {
      if (!isActiveCallback(sid, controller)) return
      assistantMsg.reasoning = (assistantMsg.reasoning || '') + chunk
      appendReasoningStep(assistantMsg, chunk)
      scheduleRender(assistantMsg)
      scheduleStreamScroll(sid)
    },
    (type, result, query) => {
      if (!isActiveCallback(sid, controller)) return
      appendTaskStep(assistantMsg, type, result, query)
    },
    () => {
      if (!isActiveCallback(sid, controller)) return
      assistantMsg.isStreaming = false
      scheduleRender(assistantMsg)
      finishGenerating(sid, { success: true })
      loadSessions()                                 // 刷新摘要，不切换视图
    },
    (err) => {
      if (!isActiveCallback(sid, controller)) return
      assistantMsg.isStreaming = false
      assistantMsg.showRegenerate = true
      assistantMsg.error = err
      scheduleRender(assistantMsg)
      finishGenerating(sid, { error: err })
    },
    attachmentPayloads,
  )

  if (!markGenerating(sid, controller, assistantMsg)) {
    controller.abort()
    rt.messages.splice(-2, 2)   // 回滚刚追加的 user / assistant 消息（回调被守卫拦截，不会写入）
    ElMessage.warning('当前对话正在生成中')
    return
  }
}

// ⑥ 停止：参数化 sid
function stopStreaming(sid = currentSessionId.value) {
  const rt = runtimes[sid]
  if (!rt?.controller) return
  const msg = rt.streamingMessage
  rt.controller.abort()
  finishGenerating(sid, { stopped: true })
  if (msg) msg.isStreaming = false
}

// ⑦ 删除：先中断
async function handleDeleteSession(s: Session) {
  // ... ElMessageBox.confirm 保持不变
  disposeRuntime(s.id)                               // 新增：先 abort + 清理
  await apiDeleteSession(s.id)
  // ... 后续 loadSessions / 切换逻辑保持不变
}

// ⑧ 卸载：中断全部流
onBeforeUnmount(() => {
  disposeAllRuntimes()
  // ... 原有监听移除保持不变
})
```

## 十、补充考量

### 10.1 错误处理与边界情况

| 场景 | 前端处理 | 后端处理 |
|------|---------|---------|
| Token 过期 / 401 | `authFetch` 统一清除 token 跳 `/login`；`disposeAllRuntimes()` 随组件卸载 | 无改动 |
| 新建对话网络失败 | `try/catch` → `ElMessage.warning`，视图与 A 的流不变 | 无改动 |
| SSE 数据中断 / error | 仅该会话 `finishGenerating({error})`，显示失败态 + `重新生成` | 无改动 |
| 同会话并发（双击） | `rt.generating` 二次校验 + `ElMessage.warning` | 不限制，由前端保证 |
| 已删除会话的迟到回调 | `isActiveCallback(sid)` 为 false → 静默丢弃 | 无改动 |
| `abort()` 后残留 token | 守卫检查 `controller.signal.aborted` → 丢弃 | 无改动 |
| 重复 `done` / `error` | `finishGenerating` 幂等：`!rt.generating` 直接 return | 无改动 |
| 会话列表中不存在 runtime | `isSessionGenerating()` 返回 false，无徽标 | 无改动 |
| 空数据列表 | 自动新建对话（沿用现有） | 无改动 |
| 大量会话同时生成 | 后台流仅做内存写入，不渲染 DOM；随删除清理 runtime | 多条独立连接，无全局锁 |

### 10.2 安全性关注点

| 关注点 | 措施 |
|--------|------|
| 跨会话数据串写 | 回调闭包捕获 `sid` + `isActiveCallback` 双重校验，消息只写入 `runtimes[sid]` |
| Token 泄漏 | 沿用 `authFetch` 注入，不新增存储 |
| XSS | 沿用现有 marked 渲染管线，不新增 `v-html` 来源 |
| 附件越权 | 沿用现有 `session_id` 隔离存储，不改动 |
| 误删正在生成的会话 | 删除前 `disposeRuntime`，避免后端继续生成但前端已无运行时 |

### 10.3 性能考量

| 场景 | 措施 |
|------|------|
| 多流并行 token 高频写入 | 后台会话不触及 DOM；`scheduleRender` 仍按消息对象 150ms 节流 |
| 后台流引发误滚动 | `scheduleStreamScroll(sid)` 增加当前会话判断 |
| 列表频繁刷新 | 只在 `done` / `error` / 新建 / 删除时调用 `loadSessions()`，不在 token 回调中调用 |
| 消息缓存增长 | 运行时随会话删除清理；单会话消息量沿用现有分页策略（50 条 / 次） |
| Markdown 图片重复请求 | 沿用 `_streamingRender` 机制：流式期间占位，`done` 后一次性渲染 |

### 10.4 兼容性规划

| 项目 | 说明 |
|------|------|
| API 向后兼容 | 后端接口零改动，完全兼容 |
| 数据库兼容 | 无 schema 变更，无需迁移 |
| 前端兼容 | 仅改组件内部实现，路由 / 组件对外契约基本不变（`ChatInput` 新增可选 `modelValue`） |
| 旧会话数据 | 历史消息结构不变，`loadMessages` 映射逻辑沿用 |
| 多标签页 | 不实时同步生成态（需求 N1），刷新后按数据库展示 |

### 10.5 测试策略

| 测试类型 | 范围 | 工具 / 方式 |
|---------|------|-----------|
| 单元逻辑测试 | `useSessionRuntimes` 的 mark / finish / dispose / 守卫幂等性 | Vitest（如项目未配置，可用浏览器控制台手动验证） |
| 前端功能测试 | 需求文档第十节 AC1~AC10 逐项 | 手动 + Chrome DevTools Network 观察多条 SSE |
| 流式测试 | 多会话并行 SSE、abort、error 分支 | DevTools 限速 / 断网模拟 |
| 回归测试 | 停止 / 重新生成 / 断连 / 分页 / 搜索 / 删除 / 401 | 按 AC11 执行 |

### 10.6 开发规范

- **命名规范**：composable `useSessionRuntimes` 小驼峰；类型 `SessionRuntime` PascalCase；Vue 文件已有命名不变。
- **注释规范**：`isActiveCallback` 的四重守卫条件必须保留中文注释，说明其防污染目的。
- **Git 提交规范**：`feat: 支持生成中新建与切换对话`、`fix: ...`、`docs: ...`。
- **类型安全**：`SessionRuntime<TMessage>` 泛型传 `UIMessage`，避免 `any`；`AbortController` 使用 DOM 内置类型。

## 十一、验收清单

> 与需求文档第十节 AC1~AC11 一一对应。

| 编号 | 验收项 | 通过标准 | 对应流程 |
|------|--------|---------|---------|
| AC1 | 生成中新建 | A 生成中点击新建成功进入 B；A 的流未中断、内容持续追加；A 列表项显示 `◉ 正在生成` | 5.1 |
| AC2 | 生成中切换 | A 生成中切到 B，A 未中断；切回 A 能看到切走期间产生的全部内容 | 5.2 |
| AC3 | 标志正确 | 列表徽标与顶部徽标按会话 ID 显示；done / error / stop / delete 后消失；列表重排后不串位 | 5.5、7.3 |
| AC4 | 并行生成 | A、B 同时生成，内容各自写入正确会话；完成一个不影响另一个 | 5.3 |
| AC5 | 停止作用域 | 在当前会话点停止，只停当前会话；后台会话继续生成 | 5.4 |
| AC6 | 失败处理 | 后台会话失败后标志消失、摘要更新；切回可见「重新生成」按钮 | 5.5 |
| AC7 | 同会话防并发 | 生成中无法在当前会话再次发送或重新生成；双击不产生第二条流 | 5.7 |
| AC8 | 删除处理 | 删除后台生成中的会话后，流被中断、运行时清理、无异常报错 | 5.6 |
| AC9 | 草稿隔离 | A 输入一半切到 B，B 的输入框为空；切回 A 草稿仍在 | 4.2、7.2 |
| AC10 | 滚动行为 | 后台流不会滚动当前会话；切回 A 时遵循「底部跟随 / 顶部保持」规则 | 7.2 |
| AC11 | 回归 | 停止、重新生成、SSE 断连、分页、搜索、删除、401 跳转保持原有行为 | 全部 |
