## 二、数据库设计

### 2.1 新建表：`users`（用户表）

```sql
CREATE TABLE IF NOT EXISTS users (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,   -- 用户 ID，自增
    username    TEXT    NOT NULL UNIQUE,              -- 用户名，唯一索引
    password    TEXT    NOT NULL,                     -- bcrypt 哈希后的密码
    role        TEXT    DEFAULT 'user',               -- 角色：'user' | 'admin'
    avatar      TEXT    DEFAULT '',                   -- 头像 URL，暂为空
    created_at  REAL    NOT NULL,                     -- Unix 时间戳
    updated_at  REAL    NOT NULL                      -- Unix 时间戳
);

CREATE INDEX IF NOT EXISTS idx_users_username ON users(username);
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `id` | INTEGER | ✅ | 自增主键 |
| `username` | TEXT | ✅ | 用户名，唯一，4-20 字符 |
| `password` | TEXT | ✅ | bcrypt 哈希密文，不可逆 |
| `role` | TEXT | ✅ | `user`（普通用户）或 `admin`（管理员），默认 `user` |
| `avatar` | TEXT | — | 头像 URL，初始为空字符串，后续迭代支持 |
| `created_at` | REAL | ✅ | 注册时间，Unix 时间戳 |
| `updated_at` | REAL | ✅ | 最后更新时间，Unix 时间戳 |

### 2.2 改造表：`sessions`（会话表）

```sql
-- 已有表结构，新增 user_id 列
CREATE TABLE IF NOT EXISTS sessions (
    id          TEXT    PRIMARY KEY,              -- UUID (hex)，已有
    title       TEXT    DEFAULT '',               -- 会话标题，已有
    user_id     INTEGER,                          -- 【新增】关联 users.id，NULL 表示匿名会话
    status      TEXT    DEFAULT 'active',         -- 'active' | 'archived'，已有
    created_at  REAL    NOT NULL,                 -- 已有
    updated_at  REAL    NOT NULL,                 -- 已有
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

**改造说明**：

| 变更类型 | 列名 | 说明 |
|---------|------|------|
| 新增 | `user_id` | 将会话与登录用户关联 |

**向后兼容策略**：旧数据 `user_id` 保持为 NULL，不影响现有匿名会话功能。查询当前用户会话时通过 `WHERE user_id = ?` 过滤。

#### 3.1.1 POST `/api/register` — 用户注册

- **功能**：创建新用户账号，密码 bcrypt 加密后入库
- **认证**：无需 Token

**请求体 (Request Body)**：
```json
{
  "username": "zhangsan",
  "password": "Abc12345"
}
```

**校验规则**：

| 字段 | 规则 | 错误提示 |
|------|------|---------|
| `username` | 非空 | "请输入用户名" |
| `username` | 4-20 字符 | "用户名至少4位字符" |
| `username` | 仅包含字母/数字/下划线 | "用户名只能包含字母、数字和下划线" |
| `username` | 唯一性（数据库 UNIQUE 约束） | "用户名已被注册" |
| `password` | 非空 | "请输入密码" |
| `password` | 8-32 字符 | "密码至少需要8位" |
| `password` | 至少包含字母和数字 | "密码需包含字母和数字" |

**成功响应 (201 Created)**：
```json
{
  "ok": true,
  "message": "注册成功",
  "data": {
    "user_id": 1,
    "username": "zhangsan"
  }
}
```

**失败响应**：
```json
// 用户名已存在 (409 Conflict)
{
  "detail": "用户名已被注册"
}

// 参数校验失败 (422 Unprocessable Entity)
{
  "detail": [
    {
      "loc": ["body", "username"],
      "msg": "用户名至少4位字符",
      "type": "value_error"
    }
  ]
}
```

---

#### 3.1.2 POST `/api/login` — 用户登录

- **功能**：验证用户名密码，返回 JWT Token 和用户信息
- **认证**：无需 Token

**请求体 (Request Body)**：
```json
{
  "username": "zhangsan",
  "password": "Abc12345"
}
```

**成功响应 (200 OK)**：
```json
{
  "ok": true,
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer",
  "user": {
    "id": 1,
    "username": "zhangsan",
    "role": "user",
    "avatar": ""
  }
}
```

**失败响应**：
```json
// 用户名或密码错误 (401 Unauthorized)
{
  "detail": "用户名或密码错误"
}
```

**JWT Token 载荷 (Payload)**：
```json
{
  "sub": 1,
  "username": "zhangsan",
  "role": "user",
  "exp": 1717286400,
  "iat": 1716681600
}
```

- `sub`：用户 ID
- `username`：用户名
- `role`：角色（`user` / `admin`）
- `exp`：过期时间（签发时间 + 7 天）
- `iat`：签发时间

---

#### 3.1.3 GET `/api/me` — 获取当前用户信息

- **功能**：通过 Token 获取当前登录用户信息，用于页面刷新时恢复登录态
- **认证**：需要 Bearer Token

**请求头**：
```
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

**成功响应 (200 OK)**：
```json
{
  "ok": true,
  "user": {
    "id": 1,
    "username": "zhangsan",
    "role": "user",
    "avatar": ""
  }
}
```

**失败响应 (401 Unauthorized)**：
```json
{
  "detail": "无效的认证令牌"
}
```

#### 3.1.4 认证中间件 `get_current_user`（新建）

**文件**：`backend/dependencies/auth.py`

**功能**：从 `Authorization` Header 中提取 Bearer Token，解码 JWT 并返回用户信息字典。

**实现要点**：
- Header 格式校验：`Bearer {token}`
- JWT 解码失败 → 返回 401 "无效的认证令牌"
- 成功返回 payload 字典 `{ sub, username, role, exp, iat }`

**使用方式**（在其他路由中注入）：
```python
from dependencies.auth import get_current_user

@router.get("/api/sessions")
async def list_sessions(current_user: dict = Depends(get_current_user)):
    user_id = current_user["sub"]
    # ...
```

#### 3.1.5 后端实现核心逻辑 (`auth_service.py`)

```python
import bcrypt
import jwt
import os
from datetime import datetime, timedelta

JWT_SECRET = os.environ.get("JWT_SECRET", "change-me-in-production")
JWT_ALGORITHM = "HS256"
JWT_EXPIRATION_DAYS = 7

def hash_password(password: str) -> str:
    """对密码进行 bcrypt 加盐哈希"""
    return bcrypt.hashpw(password.encode('utf-8'), bcrypt.gensalt()).decode('utf-8')

def verify_password(password: str, hashed: str) -> bool:
    """验证密码是否匹配 bcrypt 哈希"""
    return bcrypt.checkpw(password.encode('utf-8'), hashed.encode('utf-8'))

def create_token(user_id: int, username: str, role: str) -> str:
    """签发 JWT Token"""
    payload = {
        "sub": user_id,
        "username": username,
        "role": role,
        "exp": datetime.utcnow() + timedelta(days=JWT_EXPIRATION_DAYS),
        "iat": datetime.utcnow(),
    }
    return jwt.encode(payload, JWT_SECRET, algorithm=JWT_ALGORITHM)

def decode_token(token: str) -> dict:
    """解码 JWT Token，校验过期"""
    return jwt.decode(token, JWT_SECRET, algorithms=[JWT_ALGORITHM])
```

#### 4.2.4 密码强度计算逻辑

```typescript
function calcPasswordStrength(password: string): { level: number; label: string } {
  if (password.length < 6) return { level: 0, label: '' }
  let score = 0
  if (password.length >= 8) score++
  if (/[a-zA-Z]/.test(password) && /[0-9]/.test(password)) score++
  if (/[^a-zA-Z0-9]/.test(password)) score++
  const labels = ['', '弱', '中', '强']
  return { level: score, label: labels[score] }
}
```

### 5.4 API 请求拦截（Token 注入 + 401 全局处理）

```
┌──────────────────────────────────────────────────────────────────┐
│                    authFetch 请求拦截流程                          │
│                                                                  │
│  authFetch(url, options)                                          │
│                                                                  │
│  ┌─ 1. 获取 Token：localStorage.getItem('auth_token')            │
│  │                                                               │
│  ├─ 2. 构建 Headers：                                             │

│  │                                                               │
│  ├─ 4. fetch(url, { ...options, headers })                       │
│  │                                                               │
│  └─ 5. 检查响应 status                                           │
│        ├─ status === 401                                         │
│        │   ├─ localStorage.removeItem('auth_token')              │
│        │   ├─ localStorage.removeItem('user_info')               │
│        │   └─ window.location.href = '/login'                    │
│        │       (或 router.push，需在组件上下文中)                  │

│        └─                                                        │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

**实现**（`frontend/src/api/auth.ts` 新建）：

```typescript
const BASE = '/api'

function getAuthHeaders(): Record<string, string> {
  const token = localStorage.getItem('auth_token')
  const headers: Record<string, string> = { 'Content-Type': 'application/json' }
  if (token) {
    headers['Authorization'] = `Bearer ${token}`
  }
  return headers
}

export async function authFetch(url: string, options: RequestInit = {}): Promise<Response> {
  const headers = getAuthHeaders()
  const resp = await fetch(url, {
    ...options,
    headers: { ...headers, ...(options.headers || {}) },
  })
  if (resp.status === 401) {
    localStorage.removeItem('auth_token')
    localStorage.removeItem('user_info')
    window.location.href = '/login'
  }
  return resp
}

export async function login(username: string, password: string) {
  return authFetch(`${BASE}/login`, {
    method: 'POST',
    body: JSON.stringify({ username, password }),
  })
}

export async function register(username: string, password: string) {
  return authFetch(`${BASE}/register`, {
    method: 'POST',
    body: JSON.stringify({ username, password }),
  })
}

export async function getMe() {
  return authFetch(`${BASE}/me`)
}
```

### 7.1 前端全局认证状态 `useAuth`

**文件**：`frontend/src/composables/useAuth.ts`（新建）

```typescript
import { ref, computed } from 'vue'
import { useRouter } from 'vue-router'

interface UserInfo {
  id: number
  username: string
  role: 'user' | 'admin'
  avatar: string
}

const currentUser = ref<UserInfo | null>(
  JSON.parse(localStorage.getItem('user_info') || 'null')
)

const isLoggedIn = computed(() => !!localStorage.getItem('auth_token'))
const isAdmin = computed(() => currentUser.value?.role === 'admin')

export function useAuth() {
  const router = useRouter()

  function setAuth(token: string, user: UserInfo) {
    localStorage.setItem('auth_token', token)
    localStorage.setItem('user_info', JSON.stringify(user))
    currentUser.value = user
  }

  function logout() {
    localStorage.removeItem('auth_token')
    localStorage.removeItem('user_info')
    currentUser.value = null
    router.push('/login')
  }

  function getToken(): string | null {
    return localStorage.getItem('auth_token')
  }

  return { currentUser, isLoggedIn, isAdmin, setAuth, logout, getToken }
}
```

## 十、补充考量

### 10.1 错误处理与边界情况

| 场景 | 前端处理 | 后端处理 |
|------|---------|---------|
| Token 过期 / 无效 | authFetch 全局拦截 401 → 清除 Token → 跳转 `/login` | 返回 401 + `{"detail": "无效的认证令牌"}` |
| 网络中断 | 浏览器原生错误提示，Toast 显示 "网络连接失败" | — |
| 用户名已存在（注册） | 字段级 error 提示 + 错误条显示 "用户名已被注册" | 捕获 UNIQUE constraint，返回 409 |
| 密码错误（登录） | 表单级 error 提示 "用户名或密码错误" | bcrypt 验证失败，返回 401（不透露是用户名错还是密码错） |
| 用户不存在（登录） | 表单级 error 提示 "用户名或密码错误" | 查询无结果，返回 401（与密码错误统一提示，防止用户枚举） |
| 已登录用户访问 `/login` 或 `/register` | 路由守卫自动跳转 `/chat` | — |
| 未登录用户访问 `/chat` | 路由守卫自动跳转 `/login` | — |
| 注册时密码与确认密码不一致 | 实时校验 + 提交校验，红色提示 "两次输入的密码不一致" | — |
| 输入框在输入/失焦时清除错误样式 | `@input` 事件中清除 error 样式和错误提示 | — |
| Enter 键提交 | 用户名框 Enter → focus 密码框；密码框 Enter → 提交登录 | — |
| 并发重复注册 | 按钮 loading 态阻止二次点击 | UNIQUE 约束保证数据层面唯一性 |
| XSS 防护 | 用户输入通过 Element Plus el-input 自动转义，不渲染 HTML | — |
| SQLite 并发锁 | — | 使用 `Lock` 确保写操作串行化 |

### 10.2 安全性关注点

| 关注点 | 措施 |
|--------|------|
| 密码存储 | bcrypt 加盐哈希，不可逆，不存储明文 |
| Token 存储 | 前端 `localStorage`（当前阶段），生产环境建议改用 httpOnly Cookie |
| Token 有效期 | JWT 7 天过期，过期后需重新登录 |
| 密码强度 | 前端强制至少 8 位 + 含字母和数字，后端同样校验 |
| 登录失败统一提示 | 不区分"用户不存在"和"密码错误"，防止用户名枚举攻击 |
| XSS | Vue 模板自动转义 HTML，el-input 原生安全 |
| CSRF | SPA + Bearer Token 认证模式，天然免疫 |
| SQL 注入 | 使用参数化 SQL（`?` 占位符），原生 sqlite3 自动转义 |
| 敏感信息 | `.env` 不入 Git（已 `.gitignore`），JWT_SECRET 不下发给前端 |
| CORS | 开发环境 Vite proxy 透明代理；生产环境 FastAPI 配置 `allow_origins` |
| 密码传输 | 生产环境强制 HTTPS，避免明文传输 |

### 10.3 性能考量

| 场景 | 措施 |
|------|------|
| bcrypt 哈希 | bcrypt 哈希计算开销约 100-200ms，异步执行不阻塞主线程 |
| JWT 解码 | 无需数据库查询，纯算法验证，极轻量 |
| 路由守卫 | 同步读取 localStorage，无异步操作，零延迟 |
| 表单校验 | Element Plus 内置校验，纯客户端同步，无网络请求 |
| 密码强度实时计算 | 正则匹配，O(1) 时间，无性能影响 |

### 10.4 兼容性规划

| 项目 | 说明 |
|------|------|
| 数据库兼容 | `users` 表为新建，不影响已有表；`sessions` 表新增 `user_id` 列使用 `ALTER TABLE ADD COLUMN`，旧数据 `user_id` = NULL |
| API 向后兼容 | 新增 `/api/register`、`/api/login`、`/api/me`，不影响已有 `/api/chat`、`/api/sessions` |
| 前端兼容 | 路由守卫仅在访问受保护页面时触发，`/health` 等健康检查路径无需认证 |
| 管理员初始账号 | 通过脚本或手动 SQL 插入初始 admin 用户 |
| 页面刷新恢复登录态 | `useAuth` 从 localStorage 读取 `user_info`，初始化 `currentUser` |

### 10.6 开发规范

- **命名规范**：Vue 组件使用 `PascalCase`（`LoginView.vue`），后端路由文件使用 `snake_case`（`auth.py`），API 路径使用 `kebab-case`（`/api/login`）
- **注释规范**：关键业务逻辑添加 JSDoc（前端）/ docstring（后端），复杂算法添加行内注释
- **Git 提交规范**：`feat: 新增用户登录注册功能`、`fix: 修复注册时密码强度条不更新`，参考 [01_迭代开发规范.md](../../01_迭代开发规范.md) 5.4 节
- **类型安全**：TypeScript 严格模式，禁止 `any`（必要时使用 `unknown`），后端 Pydantic 模型覆盖所有请求/响应
- **CSS 变量**：所有色值使用设计规范定义的 CSS 变量，不硬编码色值
- **文件路径**：使用绝对路径（相对项目根目录），避免 Windows 风格路径
