# 开发文档规范

> 本规范定义智能客服平台所有开发文档的**统一结构**、**必备章节**和**内容格式**。  
> 任何功能模块的开发文档都需遵循此规范，确保文档一致性、可读性和可执行性。

---

## 一、文档元信息

每份开发文档开篇必须包含以下元信息表：

```markdown
# {序号} — {平台名称} 开发文档

> **版本**：v{major}.{minor}
> **最后更新**：{YYYY-MM-DD}
> **状态**：{待开发 | 开发中 | 已完成}
> **适用迭代**：阶段 {n}（{迭代内容简述}）
```

**要求**：
- **版本号**：使用语义化版本，小改动递增 minor，大改递增 major
- **状态**：三选一——「待开发」「开发中」「已完成」
- **适用迭代**：明确对应 `01_迭代开发规范.md` 中的哪一阶段

---

## 三、章节规范

### 3.1 项目技术架构总览

#### 3.1.1 整体架构图

必须包含 **ASCII 架构图**，覆盖以下层级：

```
浏览器客户端（所有页面组件 + 路由）
    │ HTTP/SSE
前端 API 层（统一请求封装、Token 管理）
    │ Vite Proxy /api → :8000
后端路由层（routers/，每个文件对应一个功能模块）
    │
后端服务层（services/，业务逻辑实现）
    │
数据层（数据库表 + 外部配置）
```

**格式要求**：
- 用 ASCII 框线画出完整的分层结构
- 每个组件标注**文件名**和**状态**（已有/新建/改造）
- 标注数据流向（箭头方向）

#### 3.1.2 技术栈明细

必须包含以下格式的技术栈表：

| 层级 | 技术选择 | 版本 | 用途 |
|------|---------|------|------|

**必填行**：前端框架、前端语言、构建工具、UI 组件库、路由、HTTP 客户端、状态管理、后端框架、ASGI 服务器、数据库、ORM、认证方式、加密方式、配置管理。

> 如有新增技术栈，在该节末尾补充说明。

### 3.2 数据库设计

#### 3.2.1 每张表必须包含

1. **完整 DDL SQL**（含注释）：
   ```sql
   CREATE TABLE IF NOT EXISTS table_name (
       column_name  TYPE    CONSTRAINTS,           -- 中文注释
       ...
   );
   CREATE INDEX IF NOT EXISTS idx_xxx ON table_name(column);
   ```

2. **字段说明表**：

   | 字段 | 类型 | 必填 | 说明 |
   |------|------|:--:|------|

3. **改造说明**（如为已有表改造）：
   - 列出变更的列
   - 说明向后兼容策略

4. **ER 关系图**（ASCII）：
   ```
   ┌──────────┐        ┌──────────────┐
   │  table_a │ 1───N │  table_b     │
   │          │       │              │
   │ id (PK)  │       │ id (PK)      │
   │ ...      │       │ a_id (FK)    │
   └──────────┘       └──────────────┘
   ```

### 3.3 后端 API 接口完整定义

#### 3.3.1 按模块组织

每个功能模块一个三级标题，格式：`### 3.x {模块名}（{新建/已有/改造}）`

必须标注涉及的**后端文件路径**：

```markdown
**文件**：`backend/routers/{name}.py` + `backend/services/{name}_service.py`
```

#### 3.3.2 每个接口必须包含

以四级标题定义，格式：`#### 3.x.y {METHOD} {PATH} — {功能简述}`

**必须包含以下字段（按顺序）**：

1. **功能**：一句话描述接口目的
2. **认证**：是否需要 Token / 是否需要管理员角色
3. **请求体 (Request Body)**：完整 JSON 示例 + 注释
4. **校验规则**（如有表单校验）：表格形式

   | 字段 | 规则 | 错误提示 |
   |------|------|---------|

5. **成功响应**：HTTP 状态码 + 完整 JSON 示例 + 注释
6. **失败响应**：每种错误场景的 HTTP 状态码 + JSON 示例
7. **查询参数**（GET 请求）：表格形式

   | 参数 | 类型 | 必填 | 默认值 | 说明 |
   |------|------|:--:|--------|------|

8. **SSE 事件类型**（流式接口专用）：

   | event 类型 | data 结构 | 说明 |
   |-----------|----------|------|

   + 完整 SSE 流示例

#### 3.3.3 API 路由汇总表

每个模块末尾必须包含**完整路由汇总表**：

| 方法 | 路径 | 认证 | 模块 | 说明 |
|------|------|:--:|------|------|

---

### 3.4 前端页面完整设计

#### 3.4.1 每个页面必须包含

以三级标题定义，格式：`### 4.x {页面名} \`{Component}.vue\`（{新建/改造}）`

**必须的元信息**：
```markdown
**路由**：`/path`
**文件**：`frontend/src/views/{Component}.vue`
**参考原型**：[{file}](path/to/prototype.html)（如有）
**设计规范**：[01_设计规范.md](path/to/spec.md)（如有）
```

**必须的子章节**：

1. **组件树**（ASCII 树状结构）：
   ```
   Component.vue
   ├── parent-element (说明)
   │   ├── child-element (v-model="xxx", placeholder="...")
   │   │   └── grand-child
   │   └── ...
   └── ...
   ```
   - 每个节点标注对应的 Element Plus 组件名和关键属性
   - 标注条件渲染（v-if / v-show）和循环渲染（v-for）

2. **交互逻辑**（用文本流程图描述）：
   ```
   用户操作
       → 某响应
           ├─ 分支 1 → 动作 A
           ├─ 分支 2 → 动作 B
           └─ 分支 3 → 动作 C
   ```

3. **前端校验规则**（如有表单校验）：

   | 字段 | 规则 | 错误消息 | 触发时机 |
   |------|------|---------|---------|

4. **Element Plus / UI 组件映射**（如有原型迁移）：

   | 原 HTML 元素 | UI 组件 | 关键属性 |
   |-------------|---------|---------|

5. **改造清单**（如为已有页面改造）：

   | 改造项 | 当前状态 | 目标状态 | 难度 |
   |--------|---------|---------|:--:|

6. **CSS 关键样式**（表格形式）：

   | 区域 | 样式说明 |
   |------|---------|

   - 必须使用设计规范的 CSS 变量，不硬编码色值

### 3.5 前后端交互完整流程

#### 3.5.1 每个核心流程必须包含

以三级标题定义，格式：`### 5.x {流程名称}`

**时序图（ASCII 格式）**：
```
┌──────────────────────────────────────────────┐
│               {流程名称} 完整时序              │
│                                              │
│  前端 ({Component}.vue)    后端 (FastAPI)     │
│  ────────────────         ────────────       │
│                                              │
│  1. {前端动作}                               │
│  2. {前端动作}                               │
│                                              │
│  3. ── METHOD /api/xxx ───────▶             │
│     Body: {...}             4. {后端处理}     │
│                             5. {后端处理}     │
│                                              │
│  6. ◀── STATUS { body } ─────               │
│                                              │
│  7. {前端后续动作}                            │
│                                              │
└──────────────────────────────────────────────┘
```

**必画的时序图**：
- 用户注册完整时序
- 用户登录完整时序
- 路由守卫判断流程
- API 请求拦截逻辑（Token 注入 + 401 全局处理）
- 核心业务流程（如对话 SSE、数据提交等）

### 3.10 补充考量

#### 3.10.1 错误处理与边界情况

| 场景 | 前端处理 | 后端处理 |
|------|---------|---------|

**必须覆盖的场景**：
- Token 过期 / 无效
- 网络中断
- 业务校验失败（如用户名已存在、密码错误）
- 资源不属于当前用户（403）
- 流式数据传输中断
- 空数据列表
- 并发冲突
- XSS 防护
- 数据库并发锁

#### 3.10.2 安全性关注点

| 关注点 | 措施 |
|--------|------|

**必须覆盖**：密码存储、Token 存储、Token 有效期、XSS、CSRF、SQL 注入、敏感信息保护、CORS

#### 3.10.3 性能考量

| 场景 | 措施 |
|------|------|

**建议覆盖**：列表分页、连接数控制、数据库优化、渲染优化

#### 3.10.4 兼容性规划

| 项目 | 说明 |
|------|------|

**必须覆盖**：数据库兼容策略、API 向后兼容、前端兼容、初始数据方案

#### 3.10.5 测试策略

| 测试类型 | 范围 | 工具 |
|---------|------|------|

**建议覆盖**：后端 API 测试、流式测试、前端功能测试、回归测试

#### 3.10.6 开发规范

- **命名规范**：Vue 组件 `PascalCase`，后端文件 `snake_case`，API 路径 `kebab-case`
- **注释规范**：关键业务逻辑必有注释
- **Git 提交规范**：`feat:` / `fix:` / `docs:`，参考 `01_迭代开发规范.md`
- **类型安全**：TypeScript 严格模式禁止 `any`，后端 Pydantic 覆盖所有请求/响应

## 四、格式约定

### 4.1 文本格式

| 元素 | 格式 | 示例 |
|------|------|------|
| 文件路径 | 行内代码 | `` `backend/routers/auth.py` `` |
| 组件名 | 行内代码 | `` `LoginView.vue` `` |
| API 路径 | 行内代码 | `` `POST /api/login` `` |
| HTTP 状态码 | 行内代码 + 括号说明 | `` `201 Created` `` |
| 数据库表名 | 行内代码 | `` `users` `` |
| 字段名 | 行内代码 | `` `user_id` `` |
| 环境变量 | 行内代码 | `` `JWT_SECRET` `` |
| 用户输入 | 双引号 | "注册成功" |
| 文件状态 | 括号标注 | （新建）/（已有）/（改造） |

### 4.2 代码块

- JSON：标注类型为 `json`
- SQL：标注类型为 `sql`
- TypeScript：标注类型为 `typescript`
- Python：标注类型为 `python`
- CSS：标注类型为 `css`
- Shell：标注类型为 `bash`
- ASCII 图：不标注语言，保持纯文本

### 4.3 表格对齐

所有表格使用标准 Markdown 对齐：

```markdown
| 列1 | 列2 | 列3 |
|------|------|------|
```

- 数字用右对齐 `---:`
- 勾选/状态列居中对齐 `:--:`
- 文本用左对齐 `------`

### 4.4 优先级标识

统一使用 emoji：
- 🔴 高优先级
- 🟡 中优先级
- 🔵 低优先级
- ✅ 必填/必须/已完成
- ❌ 无需/已废弃
- ⚠️ 注意事项
- 📌 重点标记

## 五、检查清单

编写完成开发文档后，对照此清单自查：

- [ ] 元信息完整（版本、日期、状态、迭代）
- [ ] 所有章节链接正确、可跳转
- [ ] 架构图覆盖全部层级（浏览器 → API → 路由 → 服务 → 数据）
- [ ] 每张数据库表有 DDL + 字段说明 + ER 关系
- [ ] 每个后端接口有：功能说明、认证方式、请求体、成功/失败响应 JSON
- [ ] 流式接口有事件类型表 + SSE 流示例
- [ ] 每个前端页面有：组件树、交互逻辑、校验规则
- [ ] 所有交互流程有时序图
- [ ] 依赖清单完整（新增包 + 新增文件 + 改造文件 + 环境变量）
- [ ] 开发顺序合理（按依赖关系排序）
- [ ] 补充考量覆盖：错误处理、安全、性能、兼容、测试、规范
- [ ] 代码块标注正确语言
- [ ] 表格格式正确对齐
- [ ] 无硬编码色值，全部使用设计规范 CSS 变量引用
- [ ] 文件路径使用绝对路径（相对项目根目录）
