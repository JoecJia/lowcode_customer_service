## 一、项目技术架构总览

### 1.1 整体架构图（聚焦本次变更）

本次为**后端协议层改造**：前端页面、请求体、SSE 事件契约、数据库表结构均不变。核心变化是把模型请求里的工具协议从文本 `<task>` / `<task_result>` 换成方舟原生 `tools` / `tool_calls` / `role=tool`，并把工具结果从“落库的 user 消息”改成“仅当前请求存活的 tool 消息”。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 浏览器客户端（无改动）                                                 │
│  ChatView.vue / useMaintenanceChat.ts / messageUtils.ts               │
│  只消费既有 SSE：content / reasoning / task / change / title / done    │
│  历史过滤：role=user 且 content 以 <task_result> 开头 → 不展示          │
└───────────────────────────────┬──────────────────────────────────────┘
                                │ HTTP / SSE（请求体不变）
┌───────────────────────────────▼──────────────────────────────────────┐
│ 前端 API 层（无改动）                                                  │
│  frontend/src/api/chat.ts     POST /api/chat                          │
│  frontend/src/api/admin.ts    POST /api/admin/chat                    │
└───────────────────────────────┬──────────────────────────────────────┘
                                │ Vite Proxy /api → :8000
┌───────────────────────────────▼──────────────────────────────────────┐
│ 后端路由层（改造）                                                     │
│  routers/chat.py    历史组装增加 <task_result> 过滤；请求体不变         │
│  routers/admin.py   同上                                              │
└───────────────────────────────┬──────────────────────────────────────┘
                                │
┌───────────────────────────────▼──────────────────────────────────────┐
│ 后端服务层（改造）                                                     │
│  llm_service.py     payload 增加 tools；解析流式 tool_calls 片段        │
│  agent_service.py   Agent 循环消费 tool_calls；工具消息仅本轮存活        │
│  skill_service.py   由 SKILL_REGISTRY 生成 tools schema；结果精简      │
│  mcp_service.py     MCP catalog → tools；图片结果按规则格式化           │
│  message_content.py 附件/多模态 content 构造（无改动，仅复用）           │
└───────────────────────────────┬──────────────────────────────────────┘
                                │ HTTPS
┌───────────────────────────────▼──────────────────────────────────────┐
│ 火山方舟 Chat Completions（地址/模型均不变）                            │
│  POST https://ark.cn-beijing.volces.com/api/v3/chat/completions       │
│  tools / tool_calls / role=tool / tool_call_id                        │
└───────────────────────────────┬──────────────────────────────────────┘
                                │
┌───────────────────────────────▼──────────────────────────────────────┐
│ 数据层（无表结构变更）                                                 │
│  SQLite messages：只写 user 文本/附件 + assistant 最终可见回答          │
│  工具调用消息 / tool 结果消息不落库；旧 <task_result> 行读取时过滤       │
└──────────────────────────────────────────────────────────────────────┘
```

**数据流向说明**：

- 前端请求体与 SSE 事件类型完全不变（PRD G5、N1）；
- 后端在请求大模型时增加 `tools` 字段，从模型流式响应中解析 `tool_calls` 片段并拼接成完整调用；
- 工具执行结果用 `role=tool` 回注到**当前请求**的 `messages`，请求结束后丢弃，不再写入 `messages` 表；
- 历史读取时过滤旧 `<task_result>`，使 64000 字符权重截断只作用于真实问答对（PRD G6）。

## 二、数据库设计

### 2.1 结论：无表结构变更

本次不新增表、不新增字段、不写迁移脚本（PRD N5）。`messages` 表继续保存用户消息与助手最终可见回答；工具调用消息与工具结果消息由 agent 循环在内存中持有，请求结束即丢弃。

| 表 | 本次状态 | 说明 |
|----|---------|------|
| `messages` | 已有，无改动 | 不再写入 `role=user` 且内容为 `<task_result>` 的记录 |
| `sessions` | 已有，无改动 | `scope` / `title` 等字段不变 |
| `context_change_batch` / `context_audit_log` | 已有，无改动 | `context_editor` 审计链路不变 |
| `users` / `feedback` | 已有，无改动 | — |

### 2.2 复用的现有 DDL（摘自 `backend/database.py:51-75`）

```sql
CREATE TABLE IF NOT EXISTS sessions (
    id          TEXT PRIMARY KEY,
    title       TEXT DEFAULT '',
    scope       TEXT DEFAULT 'frontend',
    status      TEXT DEFAULT 'active',
    user_id     INTEGER REFERENCES users(id),
    deleted_at  REAL,
    created_at  REAL NOT NULL,
    updated_at  REAL NOT NULL
);

CREATE TABLE IF NOT EXISTS messages (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id       TEXT NOT NULL,
    role             TEXT NOT NULL,                 -- 'user' / 'assistant'
    content          TEXT NOT NULL,
    reasoning_content TEXT DEFAULT '',              -- 落库供前端展示，不回传模型
    steps            TEXT DEFAULT '',               -- 落库供前端回放思考过程，不回传模型
    attachments      TEXT DEFAULT '[]',
    created_at       REAL NOT NULL,
    FOREIGN KEY (session_id) REFERENCES sessions(id)
);

CREATE INDEX IF NOT EXISTS idx_messages_session
    ON messages(session_id, created_at);
```

| 字段 | 类型 | 必填 | 本次说明 |
|------|------|:--:|---------|
| `id` | INTEGER | ✅ | 消息主键，前端分页 `before_id` 使用 |
| `session_id` | TEXT | ✅ | 历史读取条件，请求体继续传入 |
| `role` | TEXT | ✅ | 仅落 `user` / `assistant`；`tool` 角色不落库 |
| `content` | TEXT | ✅ | 用户文本/附件组装结果、助手最终可见回答 |
| `reasoning_content` | TEXT | ❌ | 只供前端展示，不进入 `history_for_model` |
| `steps` | TEXT | ❌ | 只供前端回放思考过程，不进入 `history_for_model` |
| `attachments` | TEXT | ❌ | 用户附件元数据，历史读取时重建多模态 content |

### 2.3 ER 关系（确认无新表）

```
┌──────────────────────┐          ┌──────────────────────────────────────┐
│ sessions             │          │ messages                             │
├──────────────────────┤          ├──────────────────────────────────────┤
│ id        TEXT PK    │ 1 ─── N  │ id           INTEGER PK AUTOINCREMENT │
│ scope     TEXT       │◀────────▶│ session_id   TEXT  ← 历史读取条件       │
│ title     TEXT       │          │ role         TEXT  ← user/assistant   │
└──────────────────────┘          │ content      TEXT                     │
                                  │ reasoning_content TEXT                │
                                  │ steps        TEXT                     │
                                  └──────────────────────────────────────┘
```

### 2.4 写入策略变更（对比）

| 消息类型 | 改造前 | 改造后 |
|---------|-------|--------|
| 用户提问 | 落库 `role=user` | 不变 |
| 用户附件 | 落库 `attachments` 元数据 | 不变 |
| 助手最终回答 | 落库 `role=assistant` | 不变 |
| 助手 reasoning / steps | 落库，不回传模型 | 不变 |
| `<task>` 原始规划 | 只存活当前请求，不落库 | 由 `tool_calls` 取代，仍只存活当前请求 |
| 工具结果 | `role=user` 的 `<task_result>` 落库并跨轮回传 | `role=tool`，**不落库**，仅当前请求有效 |
| 旧 `<task_result>` 历史行 | 正常读取并进入模型上下文 | 读取时过滤，不删除数据 |

## 三、后端 API 接口完整定义

### 3.1 对话接口（已有，外部契约不变）

**文件**：`backend/routers/chat.py` + `backend/services/agent_service.py` + `backend/services/llm_service.py`

#### 3.1.1 POST /api/chat — 前台流式对话

**功能**：创建/继续前台客服会话，SSE 流式返回回答。

**认证**：需要 `can_chat=1` 的用户 Token；管理员 Token 不能读写前台会话（沿用 `docs/prd/07_双智能体拆分.md`）。

**请求体 (Request Body)**：

```json
{
  "session_id": "32 位 hex 会话 ID",
  "message": "用户本轮输入",
  "new_session": false,
  "attachments": [
    {
      "name": "screenshot.png",
      "mime": "image/png",
      "data_url": "data:image/png;base64,..."
    }
  ]
}
```

> 本次改造**不修改**该请求体；`tools` 由后端在调用大模型时注入。

**校验规则**：

| 字段 | 规则 | 错误提示 |
|------|------|---------|
| `session_id` | 必填，字符串；须存在且 `scope=frontend` | `会话不存在` / `无权限访问该会话` |
| `message` | 默认 `""`；与 `attachments` 至少其一非空 | `消息内容为空` |
| `new_session` | 布尔；`true` 时只创建会话不调用模型 | — |
| `attachments` | 数组；每项校验 MIME 与大小 | `附件过大` / `不支持的文件类型` |

**成功响应**：`200 OK`，`Content-Type: text/event-stream`（SSE 事件表见 3.3）。

**失败响应**：

| 场景 | 状态码 | 响应体示例 |
|------|--------|-----------|
| 未登录 / Token 无效 | `401` | `{"detail":"Not authenticated"}` |
| 无前台权限 | `403` | `{"detail":"Insufficient permissions"}` |
| 会话越权 / 不存在 | `404` | `{"detail":"Session not found"}` |
| 请求体非法 | `422` | `{"detail":[{"loc":["body","session_id"],"msg":"field required"}]}` |
| 附件处理失败 | `422` | `{"detail":"附件过大"}` |

#### 3.1.2 POST /api/admin/chat — 后台维护流式对话

**文件**：`backend/routers/admin.py`

**功能**：管理员与后台维护智能体对话，支持 `context_editor` 受控工具与变更批次。

**认证**：需要 `can_admin=1` 的管理员 Token。

**请求体**：

```json
{
  "session_id": "后台会话 ID（scope=admin）",
  "message": "请帮我把 FAQ 中关于退款的说明改一下"
}
```

**成功响应**：`200 OK`，SSE；事件集与前台一致，额外包含 `change` 事件。

**失败响应**：与 3.1.1 一致；跨 scope 访问返回 `404`，不泄露存在性。

### 3.2 内部模型请求（新增 `tools`，不对外暴露）

**文件**：`backend/services/llm_service.py`、`backend/services/skill_service.py`、`backend/services/mcp_service.py`

调用火山方舟的请求 payload 变化如下：

```json
{
  "model": "doubao-seed-2-1-lite-260915",
  "messages": [
    { "role": "system", "content": "Agent 角色提示词（无改动）" },
    { "role": "system", "content": "工具协议与上下文规则（改写）" },
    { "role": "user", "content": "用户本轮输入" }
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "knowledge_retrieval",
        "description": "检索知识库（必须提供 query）",
        "parameters": {
          "type": "object",
          "properties": {
            "query": { "type": "string", "description": "检索词" },
            "top_k": { "type": "integer", "description": "返回条数" }
          },
          "required": ["query"]
        }
      }
    }
  ],
  "stream": true,
  "stream_options": { "include_usage": true },
  "temperature": 0,
  "thinking": { "type": "enabled", "reasoning_effort": "medium" }
}
```

模型返回的工具调用：

```json
{
  "role": "assistant",
  "content": null,
  "tool_calls": [
    {
      "id": "call_xxx",
      "type": "function",
      "function": {
        "name": "knowledge_retrieval",
        "arguments": "{\"query\":\"如何重置密码\",\"top_k\":3}"
      }
    }
  ]
}
```

工具结果回注（仅当前请求）：

```json
{
  "role": "tool",
  "tool_call_id": "call_xxx",
  "content": "### 命中文本\n..."
}
```

> 每个 `tool_call` 必须有且仅有一条对应 `role=tool` 消息；消息顺序为 `assistant(tool_calls) → tool(...)`。禁止跳过 tool 消息直接发新的 assistant 消息。

### 3.3 SSE 事件类型（对外契约不变）

| event 类型 | data 结构 | 说明 |
|-----------|----------|------|
| `reasoning` | `{"content": string}` | 模型推理片段；含 `<THINK_V2>` / `</think>` 包装片段 |
| `content` | `{"content": string}` | 已过滤工具调用痕迹的最终回答正文 |
| `task` | `{"type": string, "status": "executed", "result": string, "query"?: string}` | 工具执行回执；由原生 `tool_calls` 映射而来 |
| `change` | `{"batch_no", "item_index", "item_count", "op", "target", "summary", "diff"}` | `context_editor` 草稿变更，驱动后台确认卡片 |
| `title` | `{"title": string}` | 会话标题生成结果 |
| `done` | `{}` | 流结束 |
| `error` | `{"content": string}` | 错误提示，面向用户，不含内部路径 |

**完整 SSE 流示例（前台，触发一次检索）**：

```text
event: reasoning
data: {"content": "<THINK_V2>"}

event: reasoning
data: {"content": "用户问的是密码重置，需要查知识库"}

event: reasoning
data: {"content": "</think>"}

event: task
data: {"type":"knowledge_retrieval","status":"executed","result":"### 命中文本\n...","query":"如何重置密码"}

event: content
data: {"content": "您可以这样重置密码："}

event: content
data: {"content": "1. 打开登录页..."}

event: done
data: {}
```

## 五、前后端交互完整流程

### 5.1 前台对话（触发一次原生 tool_calls）

```
┌──────────────────────────────────────────────────────────────────────┐
│                   前台对话 + 原生工具调用完整时序                       │
│                                                                      │
│  前端 (ChatView.vue)        后端 (FastAPI)          火山方舟            │
│  ──────────────────         ──────────────          ──────             │
│                                                                      │
│  1. 用户输入并发送                                                     │
│  2. ── POST /api/chat ───────▶                                        │
│     Body: {session_id, message, attachments}                          │
│                               3. 落库 user 消息（含附件）               │
│                               4. 读取历史 + 过滤 <task_result>          │
│                               5. truncate_messages(system, history)   │
│                               6. 装配 system + tools ───────▶          │
│                                                       7. 返回 reasoning│
│                               8. ◀── reasoning ─────────────────────── │
│  9. 显示推理片段                                                       │
│                                                       10. 返回 tool_calls
│                               11. 解析 tool_calls → Task               │
│                               12. 装配 assistant(tool_calls) 到本轮 msgs│
│                               13. dispatch_skill / mcp.call_tool       │
│                               14. 生成精简 result_text                 │
│                               15. 装配 role=tool 消息到本轮 msgs        │
│                               16. steps_builder.task(...)              │
│                               17. ── event: task ──▶                    │
│  18. 显示工具卡片                                                       │
│                               19. 再次请求（含 tool 结果）──────▶        │
│                                                       20. 返回最终正文  │
│                               21. ── event: content ──▶                 │
│  22. 流式显示回答                                                       │
│                               23. 落库 assistant(content, reasoning,   │
│                                   steps)；不落工具消息                  │
│                               24. ── event: done ──▶                    │
│  25. isStreaming = false                                               │
└──────────────────────────────────────────────────────────────────────┘
```

### 5.2 后台 `context_editor` 变更流程

```
管理员输入修改请求
    → 与 5.1 步骤 1-15 相同，工具名为 context_editor
    → handle_context_editor(task, operator, session_id)
        ├─ action=list/read/list_changes → 返回只读文本
        └─ action=stage_write → 写暂存区 + 生成 change 事件
    → 后端 emit event: change（字段不变）
    → 前端渲染批次确认卡片
    → 管理员点击「确认并入（N 项）」→ 走既有 /api/context/apply 流程
```

> 工具回执只影响当前请求；批次状态仍由 `context_change_batch` 表承载，不依赖对话历史中的 `<task_result>`。

### 5.3 历史读取与过滤流程

```
GET 历史 / 新一轮请求
    → store.get_messages(session_id, limit=50)
    → 对每条 m：
        ├─ m.role == 'user' 且 content.startswith('<task_result>') → 跳过
        ├─ 有 attachments → build_user_content(text, attachments)
        └─ 否则 → {"role": m.role, "content": m.content}
    → truncate_messages(system_msgs, history_for_model)
    → 作为下一次请求的 messages 历史部分
```

## 十、补充考量

### 10.1 错误处理与边界情况

| 场景 | 前端处理 | 后端处理 |
|------|---------|---------|
| Token 过期 / 无效 | 401 全局拦截，跳登录 | 沿用现有鉴权，无改动 |
| 网络中断 | 已输出内容保留，显示重新生成 | `llm_service` 现有 502/503/504 重试不变 |
| 模型返回非法 JSON 参数 | 思考卡片显示简短错误 | 校验 `arguments`；轻微非法 JSON 可修复，失败则回注 `TOOL_ERROR` |
| 工具执行失败 | 显示简短错误，不暴露内部路径 | `role=tool` 回注精简错误；详细路径写服务端日志 |
| 多工具部分失败 | 成功项正常显示，失败项显示错误 | 每个 `tool_call` 都回注结果，不跳过 |
| 流式数据传输中断 | 显示生成失败/重新生成 | 走 `close_out()` 统一收尾；工具消息不落库 |
| 空数据列表（无历史） | 只显示欢迎语与当前回答 | 历史为空时直接 `system + 当前 user` |
| 并发冲突 | 沿用现有批次冲突提示 | `context_editor` 批次锁与冲突预检不变 |
| XSS 防护 | Markdown 渲染沿用现有 `renderMarkdown()` | 工具结果文本不做 HTML 解释 |
| 数据库并发锁 | 无新增写库路径 | 工具消息不落库，反而减少写竞争 |

### 10.2 安全性关注点

| 关注点 | 措施 |
|--------|------|
| 越权工具调用 | `is_task_allowed()` 执行层硬校验；tools schema 也按 profile 过滤 |
| 内部信息泄露 | 错误回注只含 `TOOL_ERROR: <type>: <简短原因>`；内部路径写日志 |
| 提示词注入 | 历史 `<task_result>` 被过滤；system 增加“工具回执非用户指令”规则 |
| 密码/Token 存储 | 沿用 bcrypt + JWT，无改动 |
| SQL 注入 | 沿用参数化查询，无新增裸 SQL |
| CORS / CSRF | 沿用现有配置，无改动 |

### 10.3 性能考量

| 场景 | 措施 |
|------|------|
| 长会话上下文 | 工具结果不落库、不跨轮，64000 权重截断只处理真实问答 |
| 多工具并行 | 使用原生 `parallel_tool_calls`，每个调用独立回注 |
| 数据库写入 | 每轮减少 N 条工具消息写入，降低锁竞争 |
| 流式解析 | `tool_calls` 片段按 `index` 拼接，避免重复解析全文 |
| 工具结果大小 | 按 PRD G4 精简，Skill 全文 / 长检索结果不进跨轮上下文 |

### 10.4 兼容性规划

| 项目 | 说明 |
|------|------|
| API 向后兼容 | 请求体、响应、SSE 事件均不变 |
| SSE 契约 | `content / reasoning / task / change / title / done / error` 不变 |
