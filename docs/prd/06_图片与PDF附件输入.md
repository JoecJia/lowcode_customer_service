# 06 - 图片与 PDF 附件输入需求说明

> 智能客服系统 — 对话输入框支持图片 / PDF 的粘贴、选择与拖拽
>
> 关联文档：`docs/prd/02_客服对话页.md`、`docs/dev_docs/05_图片与PDF附件输入.md`、`docs/design/design_specifications/图片输入改造方案.md`
>
> 分工：本文只定义**用户可感知的需求、交互规则与验收标准**；模型格式确认、前后端改造、附件存储与关键决策见《图片输入改造方案》（技术方案 / 决策记录），实现级说明见《05 — 图片与 PDF 附件输入开发文档》。

## 一、背景与现状

### 1.1 现状描述

当前客服对话页（`02_客服对话页.md` 区域 ⑥.1 输入框 / ⑥.2 发送按钮）只接受纯文本：

| 位置 | 现状 |
|------|------|
| 输入框（区域 ⑥.1） | 原生多行文本框，支持 Enter 发送、Shift+Enter 换行、内容自动增高；不支持粘贴图片、拖拽文件、选择文件 |
| 发送消息（3.3） | 只取输入框文本，用户消息以纯文本进入对话 |
| 消息列表（区域 ⑤） | 用户气泡只渲染文本；AI 回复中的图片来自知识检索结果，与用户输入无关 |
| 会话历史 | 消息不记录附件信息，刷新后无法回溯用户是否发送过材料 |

**问题**：用户咨询"截图里的报错怎么解决""这个 PDF 里的条款是什么意思"时，无法把材料直接交给客服智能体，只能用文字转述，导致信息缺失、追问轮数增加。

### 1.2 本次变更要解决的问题

1. 让图片和 PDF 像文字一样，作为一条普通用户消息的一部分进入对话；
2. 提供粘贴、选择、拖拽三种入口，让用户在发送前能看到并管理待发附件；
3. 附件随会话保存，刷新页面后可回显、可再次查看；
4. 不新增"识别图片 / 解析文档"等独立步骤，保持现有对话体验不变。

## 二、目标与非目标

### 2.1 目标

| 编号 | 目标 |
|------|------|
| G1 | 用户可通过粘贴、点击回形针选择、拖拽三种方式，把图片或 PDF 加入输入区 |
| G2 | 待发附件以卡片形式展示，支持在发送前逐个删除 |
| G3 | 图片 / PDF 与文字可在同一条消息中提交；纯附件（无文字）也可发送 |
| G4 | 附件作为普通多模态消息进入现有对话链路，思考过程、流式输出、技能调用、停止与重新生成行为不变 |
| G5 | 不提供独立的识别 / 解析阶段，按钮文案保持"发送" |
| G6 | 附件随会话保存，刷新、切换会话后可回显与预览 |
| G7 | 格式、大小、数量超限时给出明确、不打断输入的提示 |

### 2.2 非目标（本次不做）

| 编号 | 非目标 | 说明 |
|------|--------|------|
| N1 | 独立的"开始识别 / 解析文档"按钮、阶段或状态 | 附件与普通文本走同一条对话链路 |
| N2 | 新增 SSE 事件、识别技能或专用工具 | 沿用现有 `reasoning / content / task / done` 等事件 |
| N3 | 图片 OCR 或 PDF 本地文本抽取预处理 | 由模型按多模态能力直接理解 |
| N4 | 视频 / 音频、GIF / BMP 输入 | 首版仅 PNG / JPEG / WebP / PDF；GIF / BMP 实测后再放开 |
| N5 | 对象存储 / CDN 与多端同步 | 首版本地存储，仅保证当前部署内的回显 |
| N6 | 修改知识库检索侧的图片输出逻辑 | 检索图片预览保持现状 |
| N7 | 图片压缩、长图切片等上传前处理 | 列为后续可评估项（见第九章） |
| N8 | 在后台管理页输入附件 | 本次仅改造前台客服对话页输入框 |

## 三、附件输入交互

### 3.1 三种入口

| 入口 | 用户操作 | 系统行为 | 边界 |
|------|---------|---------|------|
| 粘贴 | 在输入框内按 Ctrl/Cmd + V | 剪贴板中存在图片 / PDF 文件时，拦截默认粘贴并将文件加入附件队列 | 仅文本或普通内容时保持系统默认粘贴行为，不拦截 |
| 选择 | 点击输入框左下角回形针图标 | 打开文件选择器（`image/*`、`application/pdf`），可多选；选中后加入附件队列 | 取消选择不产生任何变化 |
| 拖拽 | 把文件拖到输入框区域 | 拖拽悬停时输入框显示蓝色虚线高亮与引导文案；松开后仅接收白名单格式并加入队列 | 非白名单文件不接收，保持原状 |

### 3.2 待发附件队列与卡片

1. 附件以卡片形式排列在输入框上方，一个文件一张卡片，按用户添加顺序排列；
2. 卡片内容：类型图标（IMG / PDF）、单行省略的文件名、第二行显示格式与大小（如 `PNG · 727.35KB`）；
3. 每张卡片右上角有 `×`，点击即从队列移除；移除图片时同时释放本地预览；
4. 处理中的卡片显示"上传中..."与浅灰呼吸动效，处理完成后转为正常卡片；
5. 格式或大小不合规的卡片显示红色边框与具体原因，用户可手动删除；**单个失败附件不阻塞其他附件与发送**；
6. 底部状态文案：
   - 无附件：`支持粘贴、拖拽或点击上传图片`；
   - 有附件：`已上传 N 个文件`；
   - 存在处理中 / 失败项：追加 `（M 个处理中）` / `（M 个失败）`。

### 3.3 发送规则

| 项目 | 规则 |
|------|------|
| 发送条件 | 文本非空**或**附件队列非空 |
| 纯附件 | 允许只发图片 / PDF、不带任何文字；系统**不补充默认识别指令**，由模型按当前上下文直接回应 |
| 图文混合 | 图片与文字在同一条消息中提交；多图按添加顺序理解，需要引用时称"图1、图2" |
| 发送后 | 清空文本与附件队列，消息气泡立即展示已发附件；直接进入现有流式回复，无识别阶段、无额外等待 |
| 发送失败 | 文本与附件保留，便于换图或重试；错误按现有 `error` 事件展示 |

### 3.4 按钮与状态

| 状态 | 输入框 | 附件卡片 | 按钮 |
|------|--------|---------|------|
| 空闲 | 可用 | 可添加、可删除 | `发送` |
| 流式生成中 | 置灰，不可编辑，忽略新的粘贴 / 拖放 | 不可删除，隐藏 `×` | `■ 停止`（现有样式） |
| 停止 / 生成结束 | 恢复可用，已输入内容保留 | 恢复可编辑 | `发送` |

> 按钮文案**始终为"发送"**（仅流式生成中按现有规则切换为停止方块），不随附件数量变化，也不提供"开始识别"等模式切换。

### 3.5 格式、大小与数量限制

| 项目 | 限制 | 超限表现 |
|------|------|---------|
| 图片格式 | PNG / JPEG / WebP | 卡片错误态：`不支持该格式，仅支持 PNG/JPEG/WebP` |
| PDF 格式 | `application/pdf` | 卡片错误态：`仅支持 PDF 文档` |
| 单张图片 | ≤ 10 MB | 卡片错误态：`图片超过 10MB` |
| 单个 PDF | ≤ 20 MB | 卡片错误态：`PDF 超过 20MB` |
| 附件总数 | ≤ 6 | 第 7 个起拒绝加入，底部提示 `最多上传 6 个附件` |
| PDF 数量 | ≤ 1 | 第 2 个 PDF 拒绝加入，提示 `每次最多上传 1 个 PDF` |
| 附件总大小（原始） | ≤ 20 MB | 拒绝加入并提示 `附件总大小不能超过 20MB` |
| 像素 | 过小图片可能被模型拒绝，前端可提前拦截 | 提示图片尺寸过小 |

- GIF / BMP 首版拦截，待实测确认后再放开；
- 错误以**卡片内行内提示**为主，不弹全局 MessageBox，避免打断输入；
- 后端仍做一次校验兜底，失败时在对应卡片展示中文原因。

### 3.6 与普通对话的关系

1. 图片 / PDF 与文字一样，都是用户消息的一部分；模型按当前用户问题和既有对话规则正常作答，**不进入独立识别模式**；
2. 思考过程、技能调用、流式输出、停止、重新生成、切换会话等表现与纯文本对话完全一致，无新增阶段或状态；
3. 多图按添加顺序称为"图1、图2……"，回答中引用时须明确是哪一张；
4. 不编造图片 / PDF 中不可见的信息；关键内容看不清时可直接追问用户；
5. 回答中不得重复输出附件 Base64 内容或服务器文件路径。

## 四、历史消息中的附件

### 4.1 回显

1. 发送成功后，用户气泡中在文本下方展示附件卡片；纯附件消息也能正常展示；
2. 刷新页面、切换会话后再次进入，附件卡片仍在；卡片只读，无删除入口；
3. 卡片样式与输入区一致，仅去掉 `×` 与上传中状态。

### 4.2 查看与下载

| 操作 | 表现 |
|------|------|
| 点击图片卡片 | 打开现有图片预览遮罩，可放大查看 |
| 点击 PDF 卡片 | 在新窗口 / 标签页打开预览，可下载原文件 |
| 未登录点击 | 跳转登录页；登录后返回原会话 |
| 越权访问（非本人会话） | 拒绝访问并提示无权限 |

### 4.3 过期与删除

1. 附件文件被清理后，历史卡片保留但显示"文件已过期"，不阻塞文本对话与后续提问；
2. 删除会话后，该会话消息中的附件卡片随会话一并移除，文件按保留策略清理；
3. 附件的具体保留天数由产品与运维确认，不在本需求中设定。

## 六、异常场景与提示文案

| 场景 | 表现 / 提示 |
|------|------------|
| 粘贴非图片 / 非 PDF 内容 | 不拦截，保持系统默认文本粘贴 |
| 不支持的图片格式（GIF / BMP 等） | 卡片错误态：`不支持该格式，仅支持 PNG/JPEG/WebP` |
| 单图 > 10 MB | 卡片错误态：`图片超过 10MB` |
| 单个 PDF > 20 MB | 卡片错误态：`PDF 超过 20MB` |
| 附件总数 > 6 | 第 7 个起拒绝：`最多上传 6 个附件` |
| PDF 数量 > 1 | 第 2 个起拒绝：`每次最多上传 1 个 PDF` |
| 附件总大小 > 20 MB | 拒绝加入：`附件总大小不能超过 20MB` |
| 文件名含非法字符 | 拒绝加入：`文件名包含非法字符` |
| 发送中再次粘贴 / 拖放 | 输入区禁用，忽略该操作 |
| 模型图片 / PDF 解析失败 | 按现有 `error` 事件展示，回答气泡显示"重新生成"；附件保留便于换图重试 |
| 网络中断 | 沿用现有中止逻辑；附件与文本保留 |
| 未登录 / 越权预览历史附件 | 跳转登录页 / 提示无权限 |
| 历史附件文件已清理 | 卡片显示"文件已过期"，不阻塞文本对话 |
| 老会话没有附件数据 | 按纯文本会话展示，无任何兼容提示 |

## 七、对现有 PRD 的修订点

| 章节 | 原描述 | 修订为 |
|------|--------|--------|
| 区域说明 ⑥.1 | 输入框只支持文本输入 | 输入框支持文本 + 图片 / PDF 附件，附件以卡片形式置于文本区上方 |
| 3.3 发送消息 | 只发送输入框文本 | 发送内容 = 文本 + 附件队列；二者不可同时为空；纯附件允许发送 |
| 3.5 停止生成 | 生成期间输入框置灰、按钮变停止 | 保持不变，并补充：附件卡片在生成期间不可删除、隐藏 `×` |
| 区域说明 ⑤ 消息列表 | 用户气泡为文本 | 用户气泡在文本下方展示只读附件卡片，点击可预览 / 下载 |
| 七、加载状态规范 | 输入框仅有文本态 | 增加附件处理中、失败、拖拽悬停三种输入区状态 |
| 十、技术备注 | `content` 为字符串 | 用户消息可携带多模态内容；具体数据结构见技术方案与开发文档 |

## 八、验收标准

| 编号 | 验收项 | 通过标准 |
|------|--------|---------|
| AC1 | 纯文本回归 | 空输入框只输入文本时，行为与改造前完全一致 |
| AC2 | 粘贴图片 | 粘贴 2 张 PNG 后显示 2 张卡片，样式与参考图一致，按钮仍为"发送" |
| AC3 | 选择 / 拖拽入口 | 回形针选择与拖拽文件均能加入队列；拖拽有高亮；非白名单文件被忽略 |
| AC4 | 纯附件发送 | 无文字、仅图片可发送；无默认识别指令，模型按普通对话规则回应 |
| AC5 | 图文混合 | 图片 + 文字提问，回答同时覆盖两者；多图按"图1/图2"顺序引用 |
| AC6 | 纯 PDF / PDF + 图文 | 单页文字型 PDF 与扫描版 PDF 均能按普通对话返回；PDF + 图片 + 文字在同一条消息中提交 |
| AC7 | 发送链路 | 发送后不出现"识别中 / 开始识别"状态，不新增技能调用或 SSE 事件，流式渲染与思考过程不变 |
| AC8 | 按钮与停止 | 流式生成中按钮变为停止、输入区禁用、附件不可删；点击停止后行为与改造前一致 |
| AC9 | 删除与清空 | 发送前可逐个删除附件；发送成功后文本与附件队列均清空 |
| AC10 | 限额拦截 | 第 7 个附件、> 10MB 图片、> 20MB PDF、GIF / BMP、非法文件名分别被拦截且提示正确；失败卡片不影响其他附件发送 |
| AC11 | 历史回显 | 发送后刷新会话，用户气泡中图片 / PDF 卡片仍在且可预览 / 下载；卡片只读 |
| AC12 | 权限与过期 | 未登录 / 越权访问历史附件被拒绝；文件被清理后卡片显示"文件已过期"，文本对话不受影响 |
| AC13 | 重新生成 | 重新生成 / 继续追问时，模型仍能基于历史附件作答 |
| AC14 | 删除会话 | 会话删除后附件卡片随消息移除，文件可被清理任务回收 |
| AC15 | 整体回归 | 纯文本对话、技能调用、思考过程、停止 / 重新生成、会话切换与搜索均无退化 |

## 九、后续可评估项

| 项目 | 说明 |
|------|------|
| 上传前图片压缩 | 长边 > 2048px 等比压缩后再上传，需权衡理解效果与首包延迟 |
| 附件数量上限 | 当前取 6，可按实际截图场景调整为 3 或 9 |
| 长图切片 / 批量截图 | 多张长截图场景的体验优化 |
| GIF / BMP 放开 | 完成模型侧实测后再决定是否纳入白名单 |
| 保留策略与容量治理 | 附件保留天数、过期清理与用户主动删除入口 |
| 后台管理页附件输入 | 若后台维护智能体需要读取附件，另行定义需求 |
