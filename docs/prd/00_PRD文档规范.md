# 00 - PRD 文档规范

> 智能客服系统 — `docs/prd/` 目录下 PRD 文档的编写规范与模板
>
> 适用范围：`docs/prd/` 目录下全部文档。本文既是规范，也是格式示例：其标题、引言、章节编号、表格、图示与引用方式均遵循下文约定。

---

## 一、文档定位与分类

### 1.1 目录与命名

| 项目 | 约定 |
|------|------|
| 存放目录 | `docs/prd/` |
| 文件命名 | `NN_中文名称.md`，`NN` 为两位数字序号，按迭代顺序递增（当前 01~07） |
| 序号作用 | 对应开发文档 `docs/dev_docs/NN_同名文件.md`，PRD 与开发文档用同一序号配对 |
| 引用方式 | 正文引用统一使用相对仓库根目录的路径，以行内代码包裹，如 `docs/prd/02_客服对话页.md` |

### 1.2 文档类型

PRD 分为两类，编写时先确定类型，再套用对应章节模板（第三、四章）：

| 类型 | 目标 | 现有示例 |
|------|------|---------|
| 原型设计类 | 描述页面结构、区域职责、交互逻辑与跳转关系，强调"长什么样、怎么点" | 01 登录及注册页、02 客服对话页、03 管理员后台页 |
| 需求说明类 | 描述变更背景、目标边界、核心规则、异常与验收，强调"为什么做、做到什么程度" | 04 生成中新建与切换对话、05 对话名称自动生成、06 图片与 PDF 附件输入、07 双智能体拆分 |

### 1.3 关联文档约定

变更类 PRD 常与开发文档、设计方案分工协作，须在引言中声明边界，避免内容重复：

| 文档 | 职责 |
|------|------|
| `docs/prd/NN_*.md` | 用户可感知的需求、交互规则与验收标准 |
| `docs/dev_docs/NN_*.md` | 实现级方案：状态模型、接口定义、数据结构、伪代码、文件级改动清单 |
| `docs/design/` | 设计稿（`design_diagrams/`）与设计规范（`design_specifications/`） |

> 分工示例：PRD 06 引言声明"本文只定义用户可感知的需求、交互规则与验收标准；模型格式确认、前后端改造与关键决策见技术方案，实现级说明见开发文档"。

## 二、通用格式约定

### 2.1 标题与引言

每篇文档以一级标题 + 引言块开头，引言后可接若干引用行，最后以 `---` 分隔正文：

```markdown
# 06 - 图片与 PDF 附件输入需求说明

> 智能客服系统 — 一句话说明本文主题与范围
>
> 关联文档：`docs/prd/02_客服对话页.md`、`docs/dev_docs/05_图片与PDF附件输入.md`
>
> 分工：本文只定义用户可感知的需求、交互规则与验收标准

---
```

| 要素 | 约定 |
|------|------|
| 一级标题 | `# NN - 中文标题`，标题句式：原型设计类为"XX 原型设计"，需求说明类为"XX 需求说明" |
| 分隔符 | 标题与主题之间用 ` - ` 或 ` — `（现有文档两种并存，单篇内保持一致） |
| 引言 | 单行 `>` 引用，格式"智能客服系统 — 主题描述" |
| 关联文档 | 可选，多行 `>` 引用，行间以 `>` 空行分隔；逐条列出相对路径 |
| 分工声明 | 可选，变更类文档在存在配套开发文档/方案时填写 |

### 2.2 章节编号

| 层级 | 写法 | 示例 |
|------|------|------|
| 一级章节 | `## 一、`、`## 二、`……中文数字 | `## 三、核心规则` |
| 二级章节 | `### 1.1`、`### 2.1`……与所属一级章节对应的阿拉伯数字 | `### 3.2 输入与输出` |
| 三级章节 | `#### 5.8.1`……仅在原型较多时使用 | `#### 5.8.1 P1 — 悬浮维护助手入口` |
| 章节间 | 每个一级章节之间插入一行 `---` 水平分隔线 | — |

### 2.3 表格

结构化内容一律使用表格，表头与内容之间必须有分隔行：

```markdown
| 编号 | 区域名称 | 功能说明 |
|------|---------|---------|
| ① | 系统 Logo / 标题 | 展示平台品牌标识，居中显示标题 |
```

| 场景 | 推荐表格 |
|------|---------|
| 清单/属性对照 | 两列表：`项目 | 说明`、`属性 | 取值` |
| 页面/模块列表 | `序号 | 页面名称 | 所属端 | 路由` |
| 区域职责 | `编号 | 区域名称 | 功能说明` |
| 目标与边界 | `编号 | 目标`（G 系列）/`编号 | 非目标 | 说明`（N 系列） |
| 验收标准 | `编号 | 验收项 | 通过标准`（AC 系列）或 `- [ ]` 复选框列表 |
| 异常场景 | `场景 | 前端表现 | 后端处理` 或 `场景 | 处理` |

单元格内的关键约束、字段、状态值用行内代码或加粗强调，如 `can_admin = 1`、**手动结果优先**。

### 2.4 图示

#### 2.4.1 ASCII 原型

- 用代码块包裹，复杂布局可使用 ```text 标注语言；
- 使用框线字符绘制窗口与区域，区域右上角用 `[①]`、`[⑥.2]` 等编号标记交互点；
- 每个原型图后紧跟「区域说明」表格，编号与图中一一对应；
- 必要时追加「交互逻辑」小节，按 `1.` `2.` `3.` 有序步骤描述；
- 示例：现有 01/02/03 文档页面原型、04/06 文档局部原型、07 文档 P1~P5 原型。

#### 2.4.2 Mermaid 图

- 用 ```mermaid 包裹，常用类型：`flowchart TD`（纵向流程）、`flowchart LR`（横向跳转）、`stateDiagram-v2`（状态流转）；
- 节点文案使用中文，判断节点用 `{}`；
- 用 `style` 统一配色，约定如下：

| 语义 | 配色 | 示例 |
|------|------|------|
| 起点/输入 | 浅蓝 `#e1f5fe` | `style A fill:#e1f5fe` |
| 成功/终点 | 浅绿 `#c8e6c9` / `#e8f5e9` | `style P fill:#c8e6c9` |
| 失败/错误 | 浅红 `#ffcdd2` | `style Q fill:#ffcdd2` |
| 页面/状态 | 浅橙 `#fff3e0` / 浅蓝 `#e3f2fd` | `style Login fill:#fff3e0` |

### 2.5 引用、链接与强调

| 用途 | 写法 | 说明 |
|------|------|------|
| 文档引用 | `` `docs/prd/02_客服对话页.md` `` | 行内代码 + 相对仓库根目录路径，明示章节时追加 §编号或章节名 |
| 文件链接 | `[login.html](../design/design_diagrams/01_登录及注册页/login.html)` | Markdown 链接，用于设计稿等需直接打开的资源 |
| 代码位置 | `frontend/src/views/ChatView.vue:97` 或 `[auth_service.py](../../backend/services/auth_service.py#L26)` | 精确到行号，便于核对现状 |
| 提示/强调 | `> **实现要点**：……`、`> **重要区分**：……` | 引用块承载补充说明；关键约束用 `**加粗**` |
| 编号体系 | G1~Gn 目标、N1~Nn 非目标、AC1~ACn 验收项、场景 A~Z、交互点 ①~⑩ | 全文统一，便于交叉引用 |

> 路径规范：文档与链接中不得出现本机绝对路径、Windows 盘符、`file://` 协议，统一使用仓库相对路径。

## 三、原型设计类文档模板

适用于描述一个或一组页面的完整形态。章节可按页面数量裁剪，顺序保持如下：

```markdown
# NN - XX 原型设计

> 智能客服系统 — 一句话定位

---

## 设计稿                      （可选：有 HTML 设计稿时）
| 页面 | 文件 | 预览 |
> 设计规范参见：[01_设计规范.md](../design/design_specifications/01_设计规范.md)

---

## 一、涉及页面
| 序号 | 页面名称 | 所属端 | 路由 |

---

## 二、P1 — 页面原型
（ASCII 原型图 + 区域说明表 + 交互逻辑）
## 三、P2 — 页面原型          （按页面递增）
...

---

## 四、交互逻辑
### 4.1 操作一     （每个操作：有序步骤 1./2./3.）
### 4.2 操作二

---

## 五、存储 / 状态 / 图表     （按需：会话存储策略、状态流转图、数据库设计）

---

## 六、页面跳转关系           （Mermaid flowchart LR）

---

## 七、加载状态规范 / 布局规范（按需：表格化各类状态与取值）

---

## 八、技术备注               （固定收尾：| 项目 | 说明 |）
```

### 3.1 编写要点

| 章节 | 要点 |
|------|------|
| 涉及页面 | 每页一个编号（P1、P2…），注明所属端（用户前台 / 管理端）与路由 |
| 页面原型 | 区域编号与「区域说明」表严格对应；功能说明写清触发条件、边界值、异常表现 |
| 交互逻辑 | 按用户操作拆分为独立小节，步骤用有序列表；标注重定向、toast 文案、状态变化 |
| 状态/存储 | 明确数据存放位置、生命周期、是否持久化；变更说明用引用块标注 |
| 加载状态 | 覆盖所有异步场景（加载更多、切换、流式输出），说明是否改变滚动位置 |
| 技术备注 | 以 `项目 | 说明` 表格收束实现细节（框架、组件、SSE 事件、分页大小、兜底行为等） |

### 4.1 编写要点

| 章节 | 要点 |
|------|------|
| 背景与现状 | 用表格给出代码/数据位置与现状事实，再归纳问题；区分"现状实现根因"与"已有可用能力" |
| 目标与非目标 | 目标用 G 编号、动宾短句、可验证；非目标用 N 编号并写明"为什么不做"，防止范围蔓延 |
| 核心概念 | 新增概念逐一定义（字段、类型、说明）；有状态变化时补 Mermaid 状态图与派生状态表 |
| 交互流程 | 复杂变更以"场景总览表 + 场景 A/B/C 分述"组织，先给期望结果，再给操作步骤与实现要点 |
| 异常处理 | 覆盖网络失败、超时、越权、并发、重复操作、数据缺失，明确前端表现与后端处理 |
| 涉及模块 | 文件级列改动概要；明确"无需改动"的模块同样重要，避免误改 |
| 验收标准 | 与 G 系列目标对应；每条须可操作、可观察结果，禁止"体验良好"等主观表述 |
| 后续可评估项 | 收录本期明确不做但已识别的优化点，注明触发评估的条件 |

## 五、变更类文档的额外约定

对既有 PRD 做行为变更时（如 04、06），须同时做到：

| 要求 | 说明 |
|------|------|
| 声明关联 | 引言列出被修订的 PRD、配套开发文档，形成可追溯链 |
| 场景化描述 | 用"场景总览表 + 逐场景展开"覆盖新建、切换、停止、失败、删除、刷新等组合 |
| 修订点对照 | 增加「对现有 PRD 的修订点」章节，表格列 `章节 | 原描述 | 修订为`，便于回写原文档 |
| 冲突与优先级 | 对多规则并存的情况（如缓存 vs 数据库、全局锁 vs 会话锁）单列规则汇总表 |
| 验收完整 | 除新功能外，明确列出"回归项"，保证原有行为无退化 |

## 六、写作原则与发布检查清单

### 6.1 写作原则

1. **需求与实现分离**：PRD 只写用户可感知的行为与验收；内部状态模型、接口契约、数据结构放开发文档。
2. **边界先行**：先写非目标，再写目标；明确"不做什么"比"做什么"更能防止返工。
3. **可验证**：每条需求都能映射到一个验收项，验收项有明确通过标准。
4. **交叉引用**：复用既有规则时引用原文档章节，不整段复制；变更时同步维护修订点表。
5. **保持一致**：同一术语（会话/对话、scope、生成中）全文统一；编号、配色、路径风格统一。

### 6.2 发布前检查清单

- [ ] 文件名符合 `NN_中文名称.md`，序号与配套开发文档一致
- [ ] 标题、引言、关联文档、分工声明格式正确，正文以 `---` 起始
- [ ] 一级章节用中文数字、二级用阿拉伯数字，章节间有 `---` 分隔
- [ ] ASCII 图区域编号与「区域说明」表一一对应；Mermaid 图配色符合约定
- [ ] 表格含表头分隔行；G/N/AC、场景、交互点编号连续且可交叉引用
- [ ] 所有路径为仓库相对路径，无本机绝对路径、`file://` 协议或盘符
- [ ] 需求说明类含背景、目标与非目标、异常矩阵、验收标准与后续可评估项
- [ ] 变更类含修订点对照表，且已同步回写被修订的 PRD
- [ ] 验收标准逐条可操作，包含必要的回归项
