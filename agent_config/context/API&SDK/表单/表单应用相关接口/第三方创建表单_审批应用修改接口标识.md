**简要描述：**

- 第三方创建的表单或审批应用修改接口标识。新接口标识在同一单位、同一应用类型内必须唯一；表单和审批的标识相互隔离（使用sign需要与创建表单创建表单使用deptManager_*类型sign做绑定，否则无权限修改）

**请求URL：**

- http://m.oa.chaoxing.com/api/apps/forms/app/edit/appName?fid=&sign=&formId=&appName=&newAppName=&formType=&operatorUid=&enc=

**请求方式：**

- GET、POST 均可

**参数说明：**

| 参数名称 | 是否必填 | 参数类型 | 参数名称 | 参数说明 |
|:---|:---|:---|:---|:---|
| datetime | 是 | string | 生成加密串时间 | 格式：yyyyMMddHH |
| sign | 是 | string | 接口标识 | 由超星办公系统提供 |
| enc | 是 | string | 接口参数加密串 | 采用 md5 加密方式生成 |
| fid | 是 | int | 单位 ID | 单位 fid |
| formId | 否 | int | 应用 ID | 表单或审批应用 ID；与 appName 至少传一个 |
| appName | 否 | string | 原接口标识 | formId 未传时，用于定位应用 |
| newAppName | 是 | string | 新接口标识 | 同一 fid、同一 formType 下必须唯一；长度不超过 50，只允许字母、数字、下划线和点号（正则：`^[a-zA-Z0-9_.]*$`） |
| formType | 否 | int | 应用类型 | 默认 2；1 表示审批，2 表示自定义表单 |
| operatorUid | 是 | long | 操作人 ID | 操作人 UID |

**返回结果：**

（1）成功

```json
{
  "success": true,
  "msg": "更新成功"
}
```

（2）失败

```json
{
  "success": false,
  "msg": "接口标识已存在"
}
```

**接口参数配置：**

（1）接口标识类型

> sign=appsFormsData_*

（2）加密秘钥

> key=xxx

（3）加密原文字符串

参数按名称的字母序排列，示例：

```text
source="[appName=oldName][datetime=2025091714][fid=63555][formId=111][formType=2][newAppName=newName][operatorUid=73361131][sign=xxx]";
```

（4）MD5 加密操作

```text
enc=md5(source+[key]);
```

（5）结果地址

```text
http://m.oa.chaoxing.com/api/apps/forms/app/edit/appName?fid=63555&formId=111&appName=oldName&newAppName=newName&formType=2&operatorUid=73361131&datetime=2025091714&sign=xxx&enc=xxx
```

**注意事项：**

1. `formId` 和 `appName` 不能同时为空；传入 `formId` 时优先按 `formId` 定位应用。
2. `newAppName` 不能为空，长度不能超过 50，且必须匹配正则 `^[a-zA-Z0-9_.]*$`，不能与同一单位同一 `formType` 下其他应用的接口标识重复。
3. `formType=1` 为审批，`formType=2` 为自定义表单，二者接口标识分别校验唯一性。
4. `sign` 必须是该第三方应用已授权的接口标识，否则无权修改应用。
5. 生成 `enc` 时，参数名必须按字母序排列，并包含除 `enc` 外的全部请求参数。
