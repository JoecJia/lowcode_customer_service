**简要描述：**

- 自建审批审批人撤回操作接口说明

**请求URL：**
- https://office.chaoxing.com/api/approve/apps/status/user/revoke

**请求方式：**
- POST请求

**参数说明：**

|参数名称|是否必填|参数类型|参数名称|参数说明|
|:----  |:----|:----- |:----- |-----   |
|datetime |是  |string |生成加密串时间 | 格式：yyyyMMddHH|
|sign     |是  |string |接口标识 | 由超星办公系统方提供|
|enc      |是  |string |接口参数加密串 |采用md5加密方式进行生成|
|fid      |是  |int    |单位ID |单位fid|
|uid      |是  |long   |用户ID |当前审批处理人passport id|
|formUserId |是 |int    |审批数据id |审批数据主键|
|revokeNodeUniqueId |是 |long |审批节点唯一标识 |从审批人撤回权限列表接口的userRevokeList中获取|
|formId   |否  |int    |审批应用id |审批应用ID|
|formAlias|否  |string |审批应用别名 |审批应用别名|
|stateFid |否  |int    |状态单位ID |透传到审批撤回处理|
|requirePass|否|string|第三方校验类型|逗号分隔的校验类型（1 审批助手、2 基础校验、3 高级校验）；撤回场景服务端固定补全为 1,2,3，传值不影响撤回开关校验|

**返回结果**
（1）成功

* 返回数据格式：{"success":true}

（2）失败

* 返回数据格式：{"success":false, "msg":"xxx"}

**参数名变更说明：**

|原文档参数|实际参数|说明|
|:---|:---|:---|
|verifyConfig|requirePass|接口不接收 verifyConfig，传 verifyConfig=false 不会跳过撤回开关与状态范围校验|

**常见失败返回（msg = 业务码 + 文案）：**

|业务码 / msg|触发条件|
|:---|:---|
|MISSING_FID|未传 fid|
|MISSING_UID|未传 uid|
|MISSING_FORM_USER_ID|未传 formUserId|
|[3000]撤回节点参数不合法|revokeNodeUniqueId 非法|
|当前节点不可撤回|当前节点状态不允许撤回|
|[100001]未找到当前用户信息|uid 对应用户不存在|
|[500]|服务端异常|

**接口参数配置**
（1）接口标识
> sign=aprvStatusHandle_xxx

（2）加密秘钥
> key=xxx

（3）加密原文字符串
> source="[datetime=xxx][fid=xxx][formAlias=xxx][formId=xxx][formUserId=xxx][revokeNodeUniqueId=xxx][sign=xxx][stateFid=xxx][uid=xxx][requirePass=]";

（4） MD5加密操作
> enc=md5(source+[key]);

**注意事项**
（1）生成enc值的参数名称列表必须通过字母a-z的顺序依次组合

* 例如：[a=1][b=2][c=3][ei=4][ej=5]

（2）生成enc值时如果某个参数的值存在多个，在加密过程中要将这些值通过英文逗号进行组合

* 例如：[a=1,2,3,4,5,6]

（3）操作接口会在执行撤回前重新生成当前用户的userRevokeList，只有revokeNodeUniqueId存在于该列表时才允许撤回。

（4）旧版审批流数据不支持审批人撤回处理，权限列表接口不会返回可撤回节点。

（5）接口不接收 `verifyConfig`；`requirePass` 为第三方校验类型标记，不控制撤回开关。

（6）撤回仍会校验接口验签、操作人权限、节点合法性及全局/节点撤回开关。
