# Skill: 生成问题反馈表填写链接 (Feedback Form Link Generator)

## 目标
当需要引导用户填写「问题反馈表」时，将最近的对话内容总结后，通过 office-mcp 获取反馈表的填写页面链接，并以 precast 参数把总结内容预填到表单字段中，最终生成一个带预填数据的完整链接展示给用户。用户点击链接进入填写页后，只需补充少量信息即可提交，无需重复描述问题。

## 触发条件
- 无法识别用户意图、无法回答用户问题，需要引导用户提交反馈时（兜底场景）。
- 用户主动要求「提交反馈 / 填写反馈表 / 反馈问题」时。
- 对话陷入死循环需终止并引导用户反馈时。

## 前置信息（问题反馈表固定参数）
- fid：`97253`
- 表单 ID（formId）：`154231`（用户侧习惯称之为「审批id」）
- 表单类型（formType）：`0`（已验证：该反馈表以 formType=0 查询可返回字段配置与填写链接，formType=1/2 均查不到）
- 反馈表名称：办公产品问题反馈表
- 字段 alias（已确认，precast 中必须使用这些 alias）：
  | 字段 | alias | compt |
  | --- | --- | --- |
  | 产品模块 | `products` | `checklist` |
  | FID | `fid` | `editinput` |
  | 问题类型 | `question_type` | `checklist` |
  | 问题描述 | `question_description` | `richtext` |

## 执行步骤

### 第 1 步：总结最近对话
将本次会话中的关键信息整理为结构化总结，作为表单预填的数据来源。总结至少覆盖：
- **问题描述**：用户遇到的问题现象、操作路径、复现步骤、期望结果。
- **产品模块**：表单 / 审批 / 信息查询 / 图表引擎 / 数据工厂 / 聚合表 / 空间预约 / 座位预约 / 考勤管理 / 报表引擎 / 报告引擎 / 学生评价系统 / 业务流引擎 / 问卷表单 / 公文流转（按对话实际涉及模块判断）。
- **问题类型**：产品bug / 产品需求 / 产品功能不知道如何使用 / 判断需求能否实现 / 业务系统搭建指导 / 预约、中职项目对接（已沟通）/ 其他。
- **单位 fid、应用名称、表单 id、审批 id**：对话中如出现则提取。
- **测试账号**：若问题与具体用户相关，记录登录方式 / 账号 / 密码，供复现问题使用。

### 第 2 步：获取反馈表填写页面链接
调用 office-mcp 的「获取应用链接」能力（`office_form_apply_page_url`）：

```
<task><type>office-mcp.office_form_apply_page_url</type><arguments>{"formType":0,"formId":154231,"fid":97253}</arguments></task>
```

记录返回的 apply 页面基础链接（形如 `http://office.chaoxing.com/front/web/apps/forms/fore/apply?id=154231&fidEnc=...&enc=...`）。

### 第 3 步：获取反馈表字段结构
调用 office-mcp 的「获取应用字段结构」能力（`office_form_compts_info`）：

```
<task><type>office-mcp.office_form_compts_info</type><arguments>{"formType":0,"formId":154231,"fid":97253}</arguments></task>
```

逐项记录接口返回字段的 `alias`（字段别名）、`compt`（组件类型）、`label`（字段名）、`options`（选项，选择类字段才有）。
**必须使用接口返回的真实 alias 与 compt，严禁臆造或套用其他表单的 alias。**

> 说明：当前接口对 154231 返回 产品模块(alias=`products`)/FID(alias=`fid`)/问题类型(alias=`question_type`) 三个字段；「问题描述」为富文本字段，接口不返回，其 alias 固定为 `question_description`（见 4.4）。

### 第 4 步：生成 precast 参数
按以下 JSON 结构组织（`data` 为数组，每项对应一个要预填的字段）：

```json
{
  "data": [
    {"alias": "<字段alias>", "compt": "<组件类型>", "val": [<值结构>]},
    {"alias": "<字段alias>", "compt": "richtext", "val": ["<HTML>"], "content": "<HTML>"}
  ]
}
```

#### 4.1 组件类型（compt）与值结构（val）对照表
| compt | val 结构 | 示例 |
| --- | --- | --- |
| `editinput`（单行输入） | `["文本"]` | `["97253"]` |
| `editTextarea` / `edittextarea`（多行输入） | `["文本"]` | `["多行内容"]` |
| `numberInput` / `numberinput`（数字） | `["数字字符串"]` | `["123456"]` |
| `dateInput` / `dateinput`（日期时间） | `["yyyy-MM-dd HH:mm"]` | `["2026-08-30 10:00"]` |
| `radiobutton`（单选） | `[{"val":"选项"}]` | `[{"val":"选项1"}]` |
| `checklist`（多选） | `[{"val":"选项1"},{"val":"选项2"}]` | 多选可含多个元素 |
| `selectbox`（下拉单选） | `[{"val":"选项"}]` | `[{"val":"选项2"}]` |
| `selectmultibox`（下拉多选） | `[{"val":"选项1"},{"val":"选项2"}]` | |
| `contact`（联系人） | `[[{"puid":数字,"uname":"姓名"}]]` | 无法确认具体用户时省略 |
| `belonger`（所属人） | `[[{"puid":数字,"uname":"姓名"}]]` | 无法确认具体用户时省略 |
| `imagebox`（图片） | `[{文件对象}]` | 无法提供文件时省略 |
| `fileupload`（附件） | `[{文件对象}]` | 无法提供文件时省略 |
| `videobox`（视频） | `[{文件对象}]` | 无法提供文件时省略 |
| `richtext`（富文本） | `val:["富文本HTML"]` 且 `content:"富文本HTML"` | 见 4.2 |
| `detailcombox`（子表单） | `rows:[[子字段对象数组]]` | 子字段同样含 alias/compt/val |

#### 4.2 富文本字段「问题描述」生成规则
「问题描述」字段为 `richtext` 富文本类型，值必须为 HTML。默认内容（模板）如下：

```
问题详细描述：

解决问题所需主要信息：
单位fid：
应用名称：
表单id或审批id：

测试账号：（若反馈的问题与具体用户相关，请提供测试账号供复现问题使用）
登录方式：
账号：
密码：
```

对应生成的 HTML 结构如下（每行一个 `<p>` 段落，空行用 `<p><br/></p>` 表示；**生成时保持该结构不变，仅填充内容**）：

```
<p>问题详细描述：</p>
<p><br/></p>
<p>解决问题所需主要信息：</p>
<p>单位fid：</p>
<p>应用名称：</p>
<p>表单id或审批id：</p>
<p><br/></p>
<p>测试账号：（若反馈的问题与具体用户相关，请提供测试账号供复现问题使用）</p>
<p>登录方式：</p>
<p>账号：</p>
<p>密码：</p>
```

填充规则：
1. **问题详细描述**：将「问题详细描述：」下方空段 `<p><br/></p>` 替换为第 1 步总结的问题描述内容（保留 `<p>` 段落，内容直接写在 `<p>` 内）。
2. **主要信息区**：在「单位fid：」「应用名称：」「表单id或审批id：」的冒号后追加对话中提取到的对应值；对话中无法确定的留空（保留冒号即可）。
3. **测试账号区**：若问题与具体用户相关，在「登录方式：」「账号：」「密码：」后填入对话中的账号信息；否则保留原样。
4. 生成时仅填充内容，保持默认结构的段落顺序不变；不要在 HTML 中额外引入 callout-block / element-id / hr 等结构。

该字段在 precast 中的写法（`val` 与 `content` 均填填充后的完整 HTML）：

```json
{
  "alias": "question_description",
  "compt": "richtext",
  "val": ["<填充后的完整HTML>"],
  "content": "<填充后的完整HTML>"
}
```

> 「问题描述」的 alias 固定为 `question_description`，即使接口字段结构中不返回该字段，也必须将其加入 precast。

#### 4.3 字段值匹配规则（重要）
- `alias`、`compt` 必须与第 3 步接口返回**完全一致**（包括大小写，如 `editinput`、`numberinput`）。
- `val` 的结构必须与 `compt` 类型匹配（见 4.1 对照表），**结构不匹配会导致表单无法正确回填**。
- 选择类字段（checklist / radiobutton / selectbox）的选项值必须取接口返回 `options` 中真实存在的选项文本。
- 无法从对话中确认值的字段（如联系人、附件、视频）一律不放入 precast，避免填错。
- 对话中无依据的内容不得臆造，留空让用户补充。

#### 4.4 反馈表固定字段映射（必须全部放入 precast）
无论接口返回哪些字段，以下 4 个字段的 precast 条目都必须生成：

```json
{
  "data": [
    {"alias": "products", "compt": "checklist", "val": [{"val": "<产品模块选项>"}]},
    {"alias": "fid", "compt": "editinput", "val": ["<单位fid>"]},
    {"alias": "question_type", "compt": "checklist", "val": [{"val": "<问题类型选项>"}]},
    {"alias": "question_description", "compt": "richtext", "val": ["<填充后的完整HTML>"], "content": "<填充后的完整HTML>"}
  ]
}
```

取值规则：
- **products（产品模块）**：从接口返回的 options 中选取与对话最匹配的模块（表单/审批/信息查询/图表引擎/数据工厂/聚合表/空间预约/座位预约/考勤管理/报表引擎/报告引擎/学生评价系统/业务流引擎/问卷表单/公文流转）；多个模块可放多个 `{"val":"..."}` 元素。
- **fid（FID）**：填入对话中涉及的单位 fid；无法确定时默认填 `"97253"`。
- **question_type（问题类型）**：从接口返回的 options 中选取最匹配的类型（产品bug/产品需求/产品功能不知道如何使用/判断需求能否实现/业务系统搭建指导/预约、中职项目对接（已沟通）/其他）。
- **question_description（问题描述）**：按 4.2 规则生成填充后的完整 HTML。

### 第 5 步：拼接完整链接
1. 将 precast JSON 做 URL 编码（UTF-8，与普通 query 参数编码一致）。
2. 拼接规则：`<第 2 步获取的基础链接>&precast=<URL编码后的JSON>`。
   - office-mcp 返回的基础链接已包含 `?id=...&fidEnc=...&enc=...` 查询参数，因此用 `&` 连接。
   - 若基础链接无任何查询参数，则用 `?precast=...`。
3. precast 参数直接拼在链接末尾，**不要改动基础链接中的任何已有参数**。

### 第 6 步：输出给用户
向用户展示：
- 完整的反馈表填写链接（可点击）。
- 已自动预填字段的简要说明。
- 提示用户点击链接进入填写页，补充剩余信息后提交。

## 输出规范
最终回复使用以下结构：

```
根据您的描述，我已为您生成问题反馈表的填写链接（相关字段已自动预填）：

**反馈表填写链接**：[点击填写](<完整链接>)

- 已自动预填：产品模块 / 问题类型 / FID / 问题描述 等
- 请点击上方链接进入填写页，补充必要信息后提交即可。
```

## 注意事项与降级策略
- 若 office-mcp 调用失败（获取链接或字段结构失败）：降级为直接引导用户填写反馈表固定链接 `http://16q.cn/PUSjHK`，不拼接 precast。
- 生成链接后如需校验，可检查 `precast` 参数是否完整且已 URL 编码（无裸 `{`、`"`、中文等未编码字符）。
- 生成的链接仅用于引导用户填写，不要公开泄露。
